# 结 · 与原版差异设计 Roadmap v0.1

> 2026-08-29 · 基底：infinite-canvas（MIT 开源，v0.16.0）
> 原则：工程上复用画布/连线/Agent/插件等底座，不代表产品交互以画布为中心；Knot 首页是 Focus-first 的线性工作桌面，语义画布放在深层按需访问。

## 第一阶段 MVP（2026-09-27）

> **极致的聚焦，优雅的交互，便捷的连接与使用。**

本阶段交付的是一个可实际创作的 Knot 工作站，不是完整愿景：

1. **极致聚焦**：线性流是主桌面，只有一个当前 Focus；用户可以把一半以上或全屏空间交给创作，当前工作和产物清晰可见；语义画布退到深层按需使用。
2. **优雅交互**：输入区以打字、语音、快照截屏、拖拽素材为主要入口；工作卡用台前调度范式切换可恢复现场；“工作岛”只呈现活跃任务。手势同时提供点击/键盘等价操作。
3. **便捷连接与使用**：从项目/当前工作现场可直接选择并启动 Codex、Hermes；显示真实运行状态；产物保留来源，可再次明确引入，不丢失原对话与 Focus。

### 素材层最小 MVP：可靠搜集 Agent 项目与任务

> Knot 的第一种核心素材，是用户已经在 Agent 里做过的工作。

- 对用户明确连接且授权的每个 Agent，可靠搜集其项目与任务/会话；首批至少覆盖 Codex、Hermes，之后可扩展其他 Agent。
- 每条记录保留可核验的来源 Agent、稳定项目/任务 ID、标题、状态、更新时间、所属项目和原 Agent 中的打开入口；用户可按这些记录找到、打开或关联回 Knot 当前 Focus。
- 这是个人工作历史的权威入口，不是泛用网页搜索。选中项目/任务后先形成可见引用节点；其完整历史和上下文不因此自动灌入当前对话，用户再明确选择要带入的内容。
- **可靠性门槛**：说明哪些 Agent/账号/工作区已接入、最近同步时间和覆盖情况；分页/增量同步不能静默漏项；权限不足、离线或同步失败必须显式显示；无法确认完整性时不能声称“搜全了”。始终能回到源 Agent 的原项目/任务。

### 素材来源分层（按顺序构建）

| 层级 | 素材范围 | 产品要求 | 当前状态 / 下一步 |
|---|---|---|---|
| **第二层：授权的信息流与聊天记录** | 微信、飞书、Discord（“disc”按 Discord 记录）及其他获授权的社媒信息流/聊天记录 | 用户明确连接账号并授权具体范围；按平台能力选择工作区、群/频道、时间段或内容类型；以可回溯的来源节点进入 Knot，保留平台、会话/频道、时间与原始链接/ID。默认只读、最小范围；不绕过平台权限或把“授权一个账号”解释成全量任意抓取。 | **前置链路部分通过，Knot 全链路未完成**：微信→本地结构化→飞书写入/读回有实测；Knot 来源节点接入尚未实现，Discord/其他社媒未测试。复用现有采集链，先修可靠性，再补 Knot 节点接入；不整体重造。详见下方 2026-09-27 核验记录。 |
| **第三层：强事实源的联网搜集** | 经授权使用可靠的 AI 原生搜索工具，搜集官方/一手及高可信小众事实源 | 目标是降低搜索功耗与反复检索成本，不另造泛用搜索引擎。搜索结果须可核验来源、发布时间/更新时间和原文链接；优先整理成带证据出处的信息结，而非倾倒搜索结果列表。搜索工具能力与覆盖边界需先核验。 | **已有能力但不稳定**：按之确认。下一步优先对现有路径做稳定性审计、代表性查询回归和失败/降级处理；未完成验收前不另造搜索轮子，也不标成稳定可用。 |

这三层按顺序构建：Agent 工作史是素材层的最小 MVP；授权社交流与强事实源搜索是后续两类输入能力。第二层已有可复用的微信采集→飞书落库前置能力，但 Knot 原生来源节点闭环未完成；第三层进入稳定性加固阶段。两者仍需在 Knot 接入时保留权限、来源可信度和同步/搜索完整性边界。

历史采集链的内部运行明细未公开归档；其状态不作为 Knot 来源接入已完成的证据。

**MVP 闭环**：连接 Agent 并同步项目/任务 → 选择已有工作现场或新建项目 → 进入单一线性 Focus → 明确引入一项素材 → 启动 Agent 并观察真实状态 → 在流中查看可追溯产物 → 切到其他工作卡再返回，原上下文与产物仍在。不得发生隐式上下文扩张。

**阶段边界**：硬件专属节点、完整语义画布作为默认首页、系统级 Dynamic Island/全局 OS 手势属于后续；MVP 先做 Knot 内的“工作岛”与工作现场切换。若 DSH 不提供跨应用捕捉接口，快照入口必须诚实降级为显式截图/文件导入，不得伪称完整 Appshot。

## 聚焦定案（2026-09-27）

> **聚焦不是彻底留白，而是规定这一刻哪些内容可以进入行动。**

Knot 的底层允许节点、资讯、对话、工作与产物互相流通；但表层始终只有一个当前焦点。线性流展示的是当前焦点的推进路径，不是底层全部网络。

### 工作站空间与信息层级（重要定案，2026-09-27）

Knot 是 **Focus-first 的创作工作站，不是 Canvas-first 的画布工具**。面对“画布会不会让人找不到东西”的质疑，答案不是把画布做得更大、更复杂，而是让用户默认不必在空间里寻物：

- **线性流 = 桌面**：承载当前创作的对话、输入、Agent 工作过程与产物；当前工作沿时间和因果连续展开，产物留在它产生的位置。
- **工作卡片 = 台前调度**：卡片代表可恢复的工作现场；当前 Focus 在台前，其他项目/Focus/对话在后台卡组中，选择即回到原处。
- **语义空间 = 深层节点**：画布与关系图是需要时再进入的深层导航/分析空间，不是首页默认主视图，也不要求用户记住节点坐标。
- **空间承诺**：Knot 会明确邀请用户把屏幕一半以上、甚至全屏交给创作；换来连续、专注、能呈现真实过程与产物的工作空间。用户仍可调整窗口、退出或切换，不强制夺取屏幕。

因此，找回旧内容优先沿工作卡片与线性流回到“在哪个工作现场、沿什么过程产生”，只有追溯关系、浏览全局节点或重新组织图结构时才下沉到语义空间。

### Focus 定义

```ts
Focus = {
  project,       // 当前项目
  intention,     // 当前意图
  contextNodes,  // 主动引入的节点集合
  activeAction,  // 当前动作：对话 / 研究 / 工作 / 验证
  expectedOutput // 预期产物
}
```

### P0 场景卡（已确认）

| Focus 字段 | Knot 当前场景 |
|---|---|
| 项目 | Knot |
| 意图 | 收口当前 P0 定义 |
| 引入节点 | 只列明确选入的材料；默认不带入无关内容 |
| 当前动作 | 对齐 P0 的 Focus 场景与验收条件 |
| 预期产物 | 一份可确认的 P0 场景定义 |

主屏应能看到 Knot 已有产物，作为工作证据；**展示产物不等于自动将其加入对话上下文**。P0 通过条件：五项状态清楚可见，且无关节点不会自动进入对话。

### P1 核心验证脚本（产品层）

用一组固定材料走通双向信息流，先验证交互范式，不建设新的资讯搜索产品或运行时：

1. 当前 Focus 明确项目、意图和预期产物；从已有材料中选 3 个资讯结，拖入当前对话。发送前能看到已载入数量与 token 预估，并可移除单个材料。
2. 对话进入一项工作；主屏显示 Codex / Hermes 的名称与真实运行状态，运行归属当前 Focus。产出的决策简报成为新结，并能回溯到输入节点。
3. 工作结暴露一个待查问题；用户选入相关资讯结，回填原对话与同一 Focus，不另起无关对话。继续推进后产生可再次引入的新产物结。
4. 连续走 3 轮；每轮上下文只包含明确引入的节点，邻近但未选中的节点不得进入对话；产物来源可追溯。

验证材料先用项目中已有节点或预置样例；资讯抽屉与瀑布流属于 P2，P1 不因此新建搜索或推荐系统。

#### P1 通过证据

- **上下文**：实际送入 Agent 的节点必须与用户明确拖入的节点一致；取消一个节点后，实际输入也同步移除。只显示“载入 3 结”不算通过。
- **Token**：标注为“预估”；如显示模型实际用量，必须与预估分开。估算口径清楚，材料增删会同步更新。
- **Agent 状态**：Codex / Hermes 的状态来自真实控制面；同一 Focus 下各自可辨识，显示运行状态、输入范围和产物或错误。进度百分比仅在状态源真实提供时显示。
- **产物来源**：新结可追溯到输入节点、原对话、Agent 运行和预期产物；再次引入时保留来源。
- **反向回填**：召回资讯后仍在原对话、原 Focus 中，原有上下文保留，新增资讯作为明确增量。
- **三轮抗干扰**：连续三轮加入一个未选中的干扰节点；它不得进入实际 Agent 输入或产物来源。仅凭截图、文案或单轮演示不算闭环通过。

#### P1 三轮走查卡（纸面阶段）

**固定样例**：旧产物 K-01；资讯 I1/I2/I3；工作问题 Q1；回填资讯 I4；干扰节点 N1（始终不选）。所有样例节点来自 Knot 项目，不接入新的搜索/推荐系统。输入框旁提供一个紧凑的“执行者”选择器：Codex、Hermes 或 Codex + Hermes。

| 轮次 | 用户动作与主屏变化 | 预期上下文 |
|---|---|---|
| 初始 | 进入 Knot 项目；K-01 在对话流中可见并标注“未载入”；Focus 意图与预期产物明确 | 空；K-01、N1 均未载入 |
| R1 | 将 I1/I2/I3 明确拖入聊天框；显示“3 结 · token 预估”；选择 Codex + Hermes 并发送，形成工作结果与产物 K-02 | I1、I2、I3 |
| R2 | 工作结果提出 Q1；从临时选择器选 I4 并回填原对话；选择 Codex 继续，形成 K-03 | I1、I2、I3、I4 |
| R3 | 移除 I2，并明确重新引入 K-02；选择 Hermes 继续工作，形成 K-04 | I1、I3、I4、K-02 |

三轮始终属于同一 Focus F1、同一对话 D1；每次 Agent 运行有各自 runId。每轮产物都要能回溯输入节点、原对话与 Agent 运行；N1 不得进入任何一轮上下文或来源链。纸面走查只验证交互是否易懂、Focus 是否清晰；Agent 状态、实际输入和来源链必须在后续真实运行中验证，不能用样例状态冒充通过证据。

#### P1 单屏交互规则（待验证）

- 首页以单一对话流为主，只保留项目选择和紧凑的 Focus 摘要（项目、意图、上下文、当前动作、预期产物）。
- 旧产物 K-01 嵌入相关对话位置，标注“可见，未载入上下文”；查看不等于载入。
- 输入框旁只有一个轻量“执行者”选择器，可选 Codex、Hermes 或 Codex + Hermes；发送后真实运行状态以内嵌活动块呈现。
- Codex / Hermes 只在真实运行时以对话内活动块出现，标出当前状态；没有真实进度数据时不显示百分比。
- 工作结果内嵌在对话中并成为新产物结，提供输入节点、原对话、Agent 运行的来源追溯。
- **快照截屏 / Appshot（P1 输入方式）**：复刻 Codex Appshots 的核心交互——快捷键或输入区动作捕捉当前前台应用窗口，将可视截图与系统可读取文字作为一个输入节点，预览后附到当前对话；不得自动另开对话或启动 Agent。快照保留 `focusId`、`dialogueId`、来源应用/窗口、捕捉时间及原始图像/文字。Codex 官方说明其桌面端支持 macOS/Windows、可配置快捷键，捕捉前台窗口图像和可用文字。[Appshots 文档](https://learn.chatgpt.com/docs/appshots)
- 截图负责“看见当时界面”；结构化运行记录负责证明 Agent 状态、实际输入和结果。两者可并列展示，但截图不能替代真实事件/运行记录，也不能单独作为 P1 通过证据。
- **输入区下方的轻量提示/动作带**：`打字`（默认）· `语音` · `快照截屏` · `拖拽素材`。它是输入方式提示，不扩展成工具栏或新侧栏。
- **语音**进入当前对话，可保留原音频并生成可校对的转写；开始录音、停止、发送由用户明确控制，不自动启动工作。
- **拖拽素材**接受图片、视频、链接、项目引用和 Knot 原生信息流节点。原生节点保留 nodeId 与 provenance；项目引用不等于递归载入整个项目；每个拖入项在发送前可预览、排序、移除。
- 硬件输入留到后续节点开发；输入区只为后续新型节点保留一致的接入方式。
- **平台边界**：当前 Knot 仓库是 FlowGram/React 画布，源码尚未发现桌面窗口捕捉或 Appshots 接入。真正捕捉其他应用窗口与可访问文字须依赖 DSH/桌面宿主提供的权限和桥接 API；普通网页的文件/剪贴板导入只能作为降级路径，不能冒称完整 Appshots 复刻。
- “召回资讯”回填原对话与原 Focus，不新开对话。
- “+ 临时材料”打开一次性选择器；用户明确选取并拖入聊天框后才进入上下文。关闭后不留下常驻侧栏或素材区。
- P2 的底部资讯抽屉与瀑布流不在本稿中。

### 产品主次与 UI / Canvas 分层（2026-09-28）

Knot 首先是一个 Codex 类 Agent Harness，不是以画布为首页的画布产品。产品有两个层次：

- **UI 层（主层）**：项目选择、单一对话、输入方式、当前 Focus、已明确引入的素材、真实 Agent 运行状态与已完成产物。它负责工作现场的连续性；即使 Canvas 暂不可用，对话与 Agent 工作现场也不能随之消失。
- **Canvas 层（次层）**：结、绳、节点关系与语义空间，供用户按需进入、聚焦和编辑。它不是应用壳、项目导航或对话运行时；UI 层不应依赖画布节点作为唯一会话状态存储。
- **工程约束**：应用壳/会话模型与画布引擎解耦。可复用现有 FlowGram 与 Knot 节点能力，但后续可替换或卸载画布层，而不重写项目选择、对话、Agent 调度和产物流。

当前代码切片只验证分层入口与 UI 优先默认态，并展示已有产物；项目选择、真实对话 Composer、Codex/Hermes 启动仍是后续主线，不在界面上伪造完成态。

### 开发切分与实现顺序（2026-09-28）

Knot 按能力边界切分，不按页面视觉切分。台前调度、灵动岛、工作卡和工作现场恢复不是 Canvas 能力，也不是 DSH 现成 UI；它们属于 Knot 自己的工作现场内核。

```text
桌面宿主
  ↓
DSH 运行适配层
  ↓
Knot 工作现场内核
  ↓
主 UI
  ↘
   Canvas 插件
```

- **桌面宿主桥接层**：负责全局快捷键、前台窗口快照 / Appshot、托盘 / Dock / 任务栏入口、窗口置前和其他系统级能力。网页原型可以暂缺；跨应用快照与系统级入口不能在普通网页中伪造。
- **DSH 运行适配层**：负责 workspace、project、session / dialogue、Agent run、真实状态、SessionEvent、stream、followup、cancel、resume 和产物错误；不负责工作卡视觉或 Canvas。
- **Knot 工作现场内核**：负责 Project、Focus、Dialogue、AgentRun、工作卡堆栈、当前台前现场、后台现场、工作岛显示规则、上下文明确引入 / 移除和 provenance。它是台前调度与灵动岛的真实状态来源。
- **主 UI 层**：呈现单一对话流、Focus 摘要、工作卡、工作岛、现场切换器、Composer、输入方式和可追溯产物。它不能用静态卡片冒充 Agent 已启动或运行中。
- **Canvas 层**：作为独立、按需进入的插件；可读取和编辑节点投影，但不持有唯一会话状态，也不负责 Agent 启动、运行状态判断或主导航。

实现顺序：先做工作现场内核和 DSH 适配协议（可用 fixture 验证 reducer 与事件映射），再做单一对话主 UI；随后接入真实 DSH，验证真实 run / status / session event / 恢复 / 取消；最后做桌面桥接与 Canvas。旧 FlowGram 外壳切片不作为新的产品主壳或开发基线。

### Jev 评估：Knot 的可选交互决策层（2026-09-28）

本节所称 Jev 指 TypeSafe AI 的 System One Model。官方定位是：输入结构化状态和类型化问题，输出带概率分布与置信度的结构化决策；它不是聊天模型、Agent Harness 或 UI 框架。[官方介绍](https://typesafe.ai/) · [官方发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev) · [API 文档](https://api.typesafe.ai/docs)

**对 Knot 的判断：有价值，但不是主底座。** Jev 可以作为 Knot 工作现场内核旁边的“受限决策器”，帮助处理候选动作、路由、评分和是否升级人工；DSH 仍负责 Agent 运行、Session、工具和真实状态，Knot 状态机仍是 UI 行为与工作现场的权威来源。

```text
DSH 真实事件 → Knot 工作现场状态机
                         ↘
                          Jev 受限决策
                               ↓
                    候选动作 → 策略校验 / 用户确认 → 执行
```

**适合先验证的场景**

- 输入路由：在打字、语音、快照、素材引用和不同 Agent / 工作流之间做候选分类。
- 工作岛建议：在“继续、查看产物、等待、需要确认、切换现场”等有限动作中给出建议，并显示置信度或转人工。
- 产物验收：用 Noul / Score 判断来源链是否完整、是否需要补证据或重新运行；不能取代确定性的验收规则。
- 桌面交互候选选择：从已发现的窗口或有限动作中选择目标；真正执行、权限和结果验证仍由桌面宿主负责。

**不适合交给 Jev 的部分**

- 不替代 DSH Agent、对话生成、代码生成或长文本加工。
- 不决定 `agent/status`、Session 是否真实存在或运行是否已经完成。
- 不直接切换 Focus、启动 Agent、发送消息或执行高风险桌面动作。
- 不成为工作卡、灵动岛或 Canvas 的唯一状态源。

**接入约束**

- Jev 输出只能是“建议”或受限分支，最终动作由 Knot 状态机和权限策略决定。
- 每次决策记录 `decisionId`、输入状态版本、候选集合、选择、概率、置信度、阈值、最终动作和 fallback 原因。
- 高风险或低置信度场景必须升级人工；没有 Jev 时必须能确定性降级运行。
- Jev 当前处于 early access，官方性能与成本数据应视为待独立回归验证的供应方声明，不作为 Knot 已通过的证据。

**工程结论**：P0 不接 Jev，先完成工作现场内核、主 UI 和真实 DSH 事件链；P1 选一个窄场景做 Jev sidecar 试点，优先“输入路由”或“工作岛下一步建议”，通过离线固定样本、置信度阈值和人工 fallback 验证后，再决定是否扩大范围。

### 信息流动

```text
资讯 → 对话 → 工作 → 产物 → 资讯
工作 → 暴露问题 → 召回资讯 → 回填当前对话
```

节点不是被动素材。每个节点都可以被查看、勾选、拖入对话、触发工作，并继续产出新的节点。信息可以双向流通，但进入当前 Focus 必须是主动选择或明确引入。

### 交互约束

- 线性流是当前 Focus 的显影，不是唯一的数据结构。
- 主屏展示当前项目、对话、Agent 运行和产物。
- 外部资讯与未进入焦点的节点放在屏幕下方的抽屉，以瀑布流展示；拉出后浏览，拖入聊天框后才成为上下文。
- Codex / Hermes 可以并行工作，但必须挂在同一个 Focus 下，不得自行扩张成新的信息流。
- **极致 Focus ≠ 空白首页**：当前产物、决策和工作证据必须被展示；隐藏的是无关噪音，不是已经发生的工作。

## 减法原则（2026-08-29 之定）

- 与"结"设计不相符的 UI/功能**先砍入口，不删代码**（组件文件全保留）
