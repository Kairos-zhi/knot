# Knot 首轮开发启动计划

v0.1 · 2026-09-28 · 供之和拟加入的团队讨论

**这份文件回答：下一步做什么、谁来做、你要决定什么、怎样判断做成了。**

阅读方式：之先读正文，尤其第 1、5、6 节；工程负责人再读附录。正文不要求你先理解技术名词。

状态：启动计划草案，尚未批准排期、指定新成员或派工。本文继承已有产品方向；新增的场景选择、工作安排和人员配置均为建议。本次交付是文档，不是产品已通过测试的证明。

## 1. 你先看这一页

### 第一轮要得到什么

**一个你能用来连续做事的 Knot 工作站。**

你把材料放进项目，打开一个工作窗口，明确这次让 Agent 看哪些东西。Agent 真正执行，结果留下来成为可继续使用的资产。你可以补材料、移除材料、换一个 Agent 接着做，也可以收起窗口、切走、回来继续。

桌面就在工作站里面：图标和文件夹用来组织，会话窗口用来深入工作；悬浮输入栏负责输入，灵动岛负责告诉你正在发生什么。画布与连线按需查看，不是使用前提。

第一轮先把这一段做实。系统桌面上的外部浮窗、NAS、应用快照等，后面接入同一套资产和现场，不另做一套产品。

### 从现在到开工，先完成三件事

1. **查起点**：哪些方案、代码和管线能直接用，哪些只是写过，还没有跑通。
2. **验关键问题**：旧内核能否支撑新窗口，真实 Agent 能否按准确输入运行并返回可核对的结果。
3. **定首轮分工**：把工作拆成有人负责、有人验收的小件，再根据实际投入排日期。

### 你现在最需要决定什么

- 首个使用场景：建议就用“整理 Knot 自身材料，形成方案，再据此迭代”。
- 首轮边界：建议先做工作站内部桌面与真实协作，外部浮窗和设备接入后置。
- 人的投入：谁能负责核心工程、客户端交互、独立核验；各能稳定投入多少时间。

**当前没有已确认的上线日期。最大的排期缺口是工程起点和人的投入，不是还差一份更大的愿景。**

## 2. 第一轮，你实际会怎么用

下面是建议的首轮演示，也是后续验收的共同场景。使用已有、获准使用的项目材料，不为了演示新增全盘扫描或私有消息拉取。

1. **打开项目。** 你看到一个文件夹，以及里面的材料、会话和此前的产物。不用先整理一张关系图。
2. **开始处理一件事。** 打开会话窗口，选三份材料，输入“整理这轮开发要点”。输入栏明确显示当前窗口、参与的 Agent 和供给材料。
3. **让两个 Agent 分别做。** Codex 与 Hermes 各自产出；你能分清是谁做的、是否还在运行、结果在哪里。两份结果不会假装成一份共同结论。
4. **继续推进。** 加一份新材料，让 Codex 接着处理。你的原意图、窗口和已有结果还在。
5. **改变思路。** 将其中一份旧材料从当前供给中移除，加入上一轮的一份结果，让 Hermes 继续。移除供给不删除原文件，也不抹去历史。
6. **切走再回来。** 把窗口收成卡片或图标，之后展开；仍回到同一件事。已托管的任务不因关闭它的显示窗口就被取消。

这里有一个必须说清的边界：已经发给模型的内容不能撤回。移除材料约束的是后续请求；如果你主动选入的旧结果本身包含那份材料的文字，这部分仍属于你选入的内容。工程验收要区分这两件事。

### 什么叫“这一轮做成了”

- 你不用开发者在旁边指路，就能完成上述任务；遇到看不懂的操作，有记录并改进。
- 你能看出当前在处理什么、Agent 用了什么、结果从哪里来。
- 未选材料不会被预览、旧会话、自动摘要或工具读取暗中重新带入。
- 结果能继续使用，收起和恢复不会丢内容、串窗口或重复生成产物。
- 工程证据由另一位核验者复查；界面好看、按钮能点，不单独算完成。

这里验证的价值不只是“更快”：还要观察材料与思考是否真的能积累、重组，是否帮助你产生下一步。第一轮不预先承诺省时、节省 token 或创造力提升的比例。

## 3. 这轮做到哪里，哪里先不做

### 本轮要交付

- 工作站内部桌面：项目文件夹、图标、会话窗口，以及窗口／卡片／图标间的切换。
- 当前窗口的输入栏、供给材料、Agent 选择；活动摘要和结果入口。
- 从已有资产中查找、打开和引用材料；结果自动留下来源并可再次使用。
- 真实 Codex／Hermes 协作链；DSH 运行接入的实际能力验证。
- 保存、恢复、取消、异常说明，以及人和 Agent 操作同一份对象的验证。

这是需要实现并验收的范围，不表示现在已经全部具备。界面的美学要求沿用总纲：克制、低打扰、主次清楚，不伪造运行进度。

### 后续再交付

- 系统桌面上的外部浮窗、小组件、全局入口与应用快照。
- 已授权目录、NAS 和其他已链接设备的接入。
- Jev 对窗口呈现的窄试点、复杂关系编排，以及更完整的主动协作能力。

主动协作的方向不撤回：已授权范围内的自动成结、整理和维护保留；人工固定、断开和隔离不能被自动覆盖。Jev 试点不是基本自动化的前置条件。

### 本轮不重新决定

Knot 的 Agent OS 定位、工作站开发基线、共用操作内核、资产化、人的覆盖权，以及“AI 用得爽、人类看得懂”。这些已有依据。新增功能仍先查旧方案，不把全部历史候选都当成当前必须实现的需求。

## 4. 怎么安排开发周期

下面是现有五阶段路线的近期展开，不是另起一套路线。**“首轮完成”指真实协作通过验收，不指界面原型完成。**

| 推进段 | 团队做什么 | 你能拿到什么 | 何时进入下一段 |
|-|-|-|-|
| 启动轮：查清起点 | 盘点相关产物和管线、核对代码改动、确认真实测试、补最小能力验证 | 一页起点报告、关键风险、工作包和可解释的估时 | 首轮范围、实施位置、负责人和验收方式明确 |
| 样机轮：把关键动作做出来 | 并行做工作站交互样机、旧内核适配和真实运行验证 | 你可以过手的样机；哪些是真能力、哪些是模拟状态都标明 | 关键交互可理解，底层数据与运行接口有证据 |
| 首轮可用：把各段接起来 | 接入真实双 Agent，完成连续工作与失败恢复测试 | 能完成第 2 节任务的版本、问题清单与独立验收报告 | 技术核验通过，之完成体验判断 |
| 之后扩展 | 根据真实使用进入外部浮窗、来源接入、主动协作 | 每次只新增一类已验证能力 | 新能力不破坏前面已通过的行为 |

### 时间怎么定

建议采用**每周一次看结果、滚动排最近一至两周**的节奏。这是待确认的协作节奏，不是开发周期估算。

启动轮先安排一个工作周作为检查窗口：到检查点交出起点报告、已取得的验证结果、未解决问题和下一步；未完成的验证如实保留，不强行报通过。实际开始日与每天工时，等人员和权限确认后填写。

首份日历排期由工程负责人提出、核验者检查、之确认范围取舍。估时必须带上参与人、可用工时、前置依赖和主要不确定性。只有一位工程师时，核心与界面工作需要串行或降低并行量，不能沿用两人的速度。

启动轮结束后，最近的每个任务都应写清：谁负责、先等什么、交什么、谁验、预计何时交。不把三个月后的细节假装成已经确定。

### 每周你只需要看四件事

1. 上次说要交什么，这次实际交了什么。
2. 你能亲手试什么，还有什么不可靠。
3. 哪个问题需要你选择，选项和代价分别是什么。
4. 下一轮交什么，谁负责，是否改变时间或范围。

原始日志、接口字段和全部测试结果保留给执行者查，不要求你逐项追读。普通技术判断由负责人处理；范围变化、新权限、费用和发布等需要相应授权。

## 5. 人类团队怎么加入，你负责什么

### 现在就需要的职责

| 职责 | 什么时候加入 | 第一件事 | 谁作最终判断 |
|-|-|-|-|
| 产品与体验负责人：之 | 已在场 | 确认首个场景、首轮边界，亲手走一遍样机 | 之决定产品方向与取舍 |
| 核心／集成工程负责人：待确认 | 启动轮现在就参与 | 看懂旧内核和真实运行链，确认改造方法与估时 | 负责技术方案；涉及范围、成本、授权升级时交之 |
| 客户端／交互工程负责人：待确认 | 启动轮共同讨论，样机轮主责 | 把窗口、输入、状态、焦点与恢复做成能过手的体验 | 与之共同确认交互；工程质量由独立核验者复查 |
| 独立核验者：待确认，可兼职 | 启动轮就参与 | 先定义怎样证明做成，再复核交付 | 给出技术通过／不通过，不代替之判断产品价值 |

建议先凑齐这些职责，不按部门扩张。两类工程职责可以由一位合适的人兼任，但要相应调整排期；同一件交付的制作者与最终核验者必须分开。

招募或评估协作者时，可让对方围绕现有材料解释一次：哪些能复用、哪些有风险、会怎样验证、自己能投入多少时间。不要让新人从重新写产品定义开始。

小禾、Codex、DSH 中的执行 Agent 可以协助整理、实现和检查，但不算已到岗的人类编制。安鼎是 Codex 的飞书身份，也不另算一个岗位。本文不擅自给历史协作者分配新任务。

### 之需要亲自完成的事

- 选择首轮真实场景，以及什么体验你愿意接受、什么不能接受。
- 确认人选、投入、必要预算与谁能拍板；这是资源决定，不由 Agent 代填。
- 在样机和首轮可用版本上亲手操作，给出具体反馈。
- 面对范围与时间冲突时作取舍；新敏感来源、对外发布等另行确认。

你不需要逐份整理旧文档、手工转发每个回执、自己追所有技术日志，也不需要替工程负责人决定每一个字段。

### 团队没齐时，哪些工作仍可推进

整理首轮材料、补来源与缺口、准备验收样例、澄清交互，可以继续。授权明确、范围清楚的独立工程任务也可以逐项推进。

但不能把无人认领的岗位写成已到位，不能承诺团队产能，不能用 Maker 的自测代替独立验收。独立核验缺位时，交付停在“候选待验”，不会因为时间到了自动通过。

## 6. 请之确认的四项

这是待决清单，不是已确认记录。推荐项只用来帮助判断，不会因沉默自动生效。

| 要决定的事 | 建议选法 | 为什么 | 当前状态 |
|-|-|-|-|
| 第一件用 Knot 完成的真事 | 用已授权的 Knot 材料，整理方案并连续迭代 | 材料已有，之能判断质量，也能暴露输入与复用问题 | 待之确认或换场景 |
| 首轮做到哪里 | 内部桌面＋真实双 Agent＋结果复用与恢复；原生浮窗后置 | 与现有工作站基线一致，先验证同一现场是否真的成立 | 既有方向的首轮范围建议，待确认 |
| 谁能稳定参与 | 核心工程、客户端工程、独立核验分别有明确人选和投入 | 决定能并行多少、何时能交，不凭身份数量估算产能 | 人选／工时／预算待补 |
| 首次评审什么时候 | 人员与材料就绪后，启动轮用一个工作周作检查窗口 | 到点看证据和缺口，形成下一段估时，不等整理“全完” | 开始日与评审时间待约定 |

可以这样回复，不需要写长说明：

> 场景：同意建议／改为……；范围：同意／调整……；人员：已有……、每周能投入……；首次评审：……。

没有现成人选也可以直接写“暂无”。计划会按现有能力拆分，不把招聘当作所有准备工作的前置条件。

## 7. 准备轮实际要做的事

这部分可直接交给拟加入的负责人，先评估再认领。本文件本身没有向任何人发出任务。

**第一步，盘点首轮会用到的东西。** 从现有总纲、复用对照和工作流来源开始，不重读全部历史。把“已设计、代码已有、历史实跑、当前可复现、尚未覆盖”分开写。

**第二步，沿一件任务检查三条链。** 信息有没有送到该做决定的人和 Agent；研发派工有没有真正发出并收回；产品窗口有没有正确使用材料并保留结果。第 8 节列了目前的起点。

**第三步，做最小验证与交互样例。** 工程侧证明一组旧操作可保存恢复、一个真实运行可追踪；交互侧让你看懂“看材料”和“把材料交给 Agent”的区别。不同任务在明确接口、互不覆盖文件的前提下并行。

**第四步，联合评审。** 工程负责人说明能做什么、风险和估时；核验者指出证据不足处；之决定范围。之后把最近一至两周的工作落实到既有任务卡和台账，不再建另一套管理系统。

准备轮停止继续扩写的条件：首轮相关能力有出处、有主责或明确缺位、有验证方法；阻塞项已经变成具体技术验证或人工决定。与首轮无关的旧资料只留指针，不阻塞开工。

每项补齐六个字段即可：来源／实现入口、当前状态、实际消费者、权限范围、最近验证证据、负责人及最小缺口。找不到只记“本轮未找到”，不推断项目从未设计。

## 9. 可拆分的工作包

编号只用于本计划引用；实际执行复用现有任务卡 ID，不另建台账。各包认领时需填写具体人名、开始日、预计交付日、可用工时、修改域与独立 Checker。

## 10. 必须保留的验收与失败场景

沿用已有三轮场景，不新增一套样例替换它。样例先固定获准使用的文件和版本。

| 轮次 | 人的动作 | 机器侧要核对什么 |
|-|-|-|
| 开始前 | 仅预览 K-01、N1，不加入供给 | 两者不进入请求；输入选择不受普通预览影响 |
| 第一轮 | 供给 I1、I2、I3，Codex 与 Hermes 分别处理 | 同一现场 F1／对话 D1，两次独立运行；分别记录来源，指定其中一个真实结果为 K-02 |
| 第二轮 | 增加 I4，由 Codex 继续 | 实际输入为 I1、I2、I3、I4；原现场连续；形成 K-03 |
| 第三轮 | 移除 I2，加入 K-02，由 Hermes 继续 | 实际输入为 I1、I3、I4、K-02；不递归带回 I2；形成 K-04 |

K-03/K-04 成为资产，但默认不自动加入当前供给。对 I2 的排除验证使用未出现在 K-02 中的专属标记，避免把用户主动选择的 K-02 内容误判为泄漏。另查工具权限，不能只看请求文本。

首轮还必须覆盖：

- 收起、展开、切换窗口后，草稿、材料选择和运行归属不混乱。
- 保存再恢复，块内容、来源、关系与新增现场字段不丢失。
- 取消／失败不显示成成功；重复事件不重复生成正式产物。
- 回执丢失或状态不明，先核对是否已执行，不直接重跑有副作用的动作。
- 自动整理尊重人工固定与断开；尚未授权的来源不进入运行。
- 窗口关闭与运行退出区分；重启后可恢复，或如实标明失联及恢复方式。

原生浮窗跨屏、捕捉拒绝、NAS 离线等测试属于后续接入门。本轮不能因未覆盖而宣称这些能力已完成，也不将它们误作内部工作站首轮的前置条件。

已记录的真实测试入口为 `ts-check`、本地 `tsx` 断言和 `build:prod`；执行前重新检查脚本内容。前轮读码发现普通 `build/test` 是空操作，其成功退出不能当作通过。[S2][S3]

## 13. 小词表与本次交付边界

- **资产**：可再次引用、组合和加工的材料或结果，不是某个窗口的副本。
- **现场／Focus**：正在处理的这件事及其意图、会话、材料选择、参与 Agent 和运行记录；不是鼠标当前点中的对象。
- **供给／V_b**：这次明确交给 Agent 使用的内容；预览和文件夹归属不自动等于供给。
- **HUD**：用于当前现场输入的轻量悬浮输入栏。
- **内核**：人和 Agent 共同调用的一套数据与操作规则；界面是它的一种使用方式。
- **Harness／运行环境**：承载 Agent 执行、会话和工具的程序；适配器负责让 Knot 与它对接。
- **Run／运行**：一次可追踪的执行；同一会话可以有多次运行，运行完成也不等于交付已验收。
- **Maker／Checker**：制作者与独立核验者。同一交付不能自己作最终验收。
