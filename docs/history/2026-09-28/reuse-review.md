# Knot · 既有方案复用与改造对照

2026-09-28 · 配套开发方案 v0.2。范围：本轮相关既有方案、调研索引及主代码接缝；不是全部历史材料、远端 PR 或全部代码的完成度审计。

## 1. 结论

AI 原生标准、开放接入、操作内核、事件与快照、块资产化、自动织养、人类可读性和开发基线都有既有积累。新需求主要改变人的入口与工作现场承载。改造应保留语义与协议、抽离渲染依赖、补真实运行与 OS 呈现。

发现两类重复：同一能力换名重造；历史提案／修正／冻结结果混在内容包中，看起来像多个现行方案。去重应按能力与决策状态进行，不按标题相似度删文档。

最新层次已明确：工作站解决详细操作；桌面可以在工作站内，也可通过外部浮窗／小组件呈现同一会话或文件夹。它们不是三套产品或互斥模式。

## 4. 材料内部需标注的冲突

1. 协议开头 DRAFT 与末尾冻结并存：采用 §7 冻结决策；本轮未改原文。
2. AGENT_FRIENDLY 的“内核未建／接口空白”落后于代码：宪法继续有效，旧状态节不作为当前缺口。
3. 8/30 审计是修复前证据：当前内核、桥、seq／锁及测试存在，但本轮没有运行通过证明。
4. MCP-only、MCP＋A2A＋拓扑、A2UI、方案 C 分属不同轮次／层次：不能把研究候选全部标成同时生效的协议基线。
5. 视觉选中、节点焦点、V_b 与工作现场 Focus 不同：预览不能等于授权，HUD 不能随普通节点选择串现场。
6. 图标＝归档混淆呈现与生命周期：图标可能仍在运行。
7. 旧节点尺寸／焦点物理重排不直接适用于 OS 工作窗口：继承渐进披露、留白与层次，重验承载。
8. 自动织养与精确输入不是全局二选一：维护组织不能越 V_b 或覆盖人工排除；输入验证也不能抹掉主动创造能力。
9. “所有竞品都没有”“token 必降某比例”等属于历史判断／供应方说法／待实验承诺：总纲不作为已证事实发布。
