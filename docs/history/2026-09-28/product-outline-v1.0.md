## 1. 一页看懂

**Knot 是 Agent OS 新范式。当前开发基线是工作站。**

它给人和 Agent 一个共同的工作环境：想法、材料、会话、文件、产物和可连接的能力，都可以成为持续生长、可引用、可重新组合的资产。人用直接、熟悉的交互操作；Agent 用原生数据和命令参与同一个现场。

人的一侧：图标和文件夹组织东西，工作窗口处理事情，HUD 接受输入，灵动岛显示活动，小组件放在角落。画布与连线按需出现。

Agent 的一侧：读得到状态，调得动操作，接得进不同宿主，听得到变化。已有的操作内核、快照、命令与事件，是这些能力的基础。

**工作站负责详细操作；桌面负责摆放、组织和随时翻阅。** 桌面可以就在工作站内部。用户也可以把同一个会话或文件夹放到外部浮窗／小组件；深入工作时展开的仍是原现场，内容、连接、状态接得上。

Knot 可以让出大部分屏幕，也可以完整占满屏幕。占屏大小是人的选择，资产身份和运行状态不随之改变。

现在的工作重点：

1. 复用已做的 AI 原生方案，抽离旧呈现依赖。
2. 建立 OS 逻辑的工作站、桌面和轻入口。
3. 跑通真实 Agent、准确上下文、可恢复现场与产物来源。
4. 再接系统级浮层、应用快照与已链接设备。

一句验收标准：**用户能连续完成一件真实的创造性工作，切走再回来，人与 Agent 都知道当前是什么、用了什么、发生了什么、下一步能做什么。**

## 2. 它为谁存在，解决什么

### 2.1 首批场景

既有定位围绕思考与创作：对谈、研究、材料组织、方案推演、写作和协作产出。它们通常不是一次问答结束，而是在材料、判断、分支与结果之间来回发展。

首批验证不应同时覆盖所有人。沿用既有路线：先用自己的真实项目验证，再邀请外部创意者完成同类任务。过去计划提出过 3 位外部创意者访谈；本轮未找到完成证据，所以它仍是可复用的验证任务，不是已有用户成绩。

### 2.2 需要形成的价值

- **现场连续**：切换后能回到原意图、对话、材料、Agent 和结果。
- **思考可积累**：会话片段、选择、产物成为有来路的资产，可继续生长、拆分、嫁接和使用。
- **连接便捷**：本地／云端 Agent、文件、已链接设备逐步通过统一接入方式成为可用节点。
- **主动共创**：Agent 能维护组织、提出灵感和协作；人保留设计路线、改连线、隔离和接管的权力。
- **理解成本低**：完整结构可供 Agent 使用，人优先看到此刻该知道、该决定的东西。

这些是产品目标。节省时间、减少重复上下文、降低 token 消耗和提升创造性，均需要实测；本纲不预报收益比例或市场份额。

## 3. 哲学与范式：哪些东西一直没变

### 3.1 思考资产化

结既是信息／思考的单元，也是协作的单元和工作环境中的资产。它可以是材料、会话片段、决策或结果。重点在于它能被继续使用，而不只是留下记录。

已有块模型支持有序内容、生长与来源；“生成自动成结”“摘要能展开回原文”“产物带 provenance”是已形成的设计基础。实现应保留这些颗粒，不能把所有资产压成一张只有标题和摘要的静态卡片。

### 3.2 人与 Agent 共用一套环境

已有 AGENT_FRIENDLY 的定案是：工作台对 Agent 要像文件系统对程序一样自然。原生感知、原生调度、开放接入是开发基石。人的手势与 Agent 命令操作同一份语义空间。

“人2a2a”在这里描述人—Agent—Agent 的协作关系，不等于新增一套专有 A2A 协议。Knot 已有自己的业务操作面；外部运输、工具接入和 UI 声明按适配层处理。

### 3.3 自动织养，手动覆盖

已有交互模型 v0.2 明确：Agent 做养护，人做设计。自动生成、整理和维护可以在已授权范围内发生；用户可以拖拽修正、连接网外资产、隔离对话、断开关系。

因此不能把 AI 原生做成“每一步等用户确认”。也不能以自动化为由暗中引入未授权材料，或把用户刚剪断的供给重新接回。

### 3.4 AI 用得爽，人类看得懂

既有 9/6 人类可读性原则已经要求双层交付：给人结论、决定点和下一步；给 AI／执行层完整规格、来源、证据和备选。产品界面也按这个原则组织。

开发团队使用任务卡、回执和独立验收；用户界面不必展示整套治理仪式。原纲领已经提醒过：保留治理的骨架，降低人的使用负担。

### 3.5 从个人工作到协作范式

历史思想材料把个人结网与社区协作看作同一逻辑的两个尺度：个人产出案例，协作实践反馈产品，产品积累可复用资产。这个方向保留。

但社区、市场、贡献值、主题商店与商业化并不是首轮工作站的前置条件。不能把长线愿景全部塞进 MVP，也不能用愿景替代真实使用验证。

## 4. 长什么样：工作站、桌面与外部呈现

本文中“工作台／工作站”指当前完整工作环境；“桌面”是其中或其外部的对象组织与取用空间。

```text
工作站：完整编辑、组织、协作、运行、检查
  └─ 内部桌面：会话窗口、项目文件夹、图标、卡片
       ├─ HUD：当前现场输入
       ├─ 灵动岛：活动状态
       └─ 角落小组件：轻功能与快捷入口

同一会话／文件夹可按用户选择呈现到外部
  ├─ 悬浮窗口：随时翻阅、查看状态
  └─ 小组件：紧凑呈现、打开原现场
          └─ 深入操作时恢复同一个工作站现场
```

这不是三个互斥模式。完整工作站和外部小组件可以同时存在；用户也可以全部留在工作站内。工程上必须分开“对象”与“呈现实例”：多个入口引用同一 ID，不能生成内容分叉。

### 4.1 OS 逻辑的职责分配

| 对象／区域 | 职责 | 避免的混淆 |
|-|-|-|
| 图标 | 稳定身份与快速打开 | 图标化不等于归档或停止 |
| 文件夹 | 项目／逻辑组织 | 移入不自动搬动物理文件或改 Agent cwd |
| 工作窗口 | 深入处理当前现场 | 窗口是资产化工作对象，不要求每个对象一个 OS 进程 |
| 卡片 | 现场的中等信息量呈现 | 不另造对话副本 |
| HUD | 输入、Agent 选择、当前供给确认 | 始终显示作用对象，不因预览别的素材串窗 |
| 灵动岛 | 活动摘要、待确认、完成／错误入口 | 不成为通知瀑布，不伪造百分比 |
| 右上／右下小组件 | 已启用的轻功能与现场入口 | 不把完整工具栏永久铺满屏幕 |
| 唤出器 | 找节点、找现场、找已链接来源 | 搜到与预览不等于输入授权 |
| 关系视图 | 需要时看连接、来源、路径 | 关闭它，主工作流程仍可完成 |

### 4.2 内外承载的边界

首轮交付内部桌面；中期交付原生浮窗／小组件。外部入口优先满足翻阅、状态和恢复现场，详细编辑回完整工作站。具体轻编辑能力以组件声明为准，不默认每个小组件都是缩小版全功能工作站。

移出、收回、全屏、收起只改变呈现。关闭实例不删除资产、不剪绳、不取消 Run；这些是独立操作。原生跨屏、输入焦点和权限须实机验证。

## 5. 交互如何发生

### 5.1 一次完整工作

打开项目文件夹 → 从图标／卡片恢复现场 → HUD 接着原意图输入 → 唤出并供给材料 → 选择一个或多个 Agent → 灵动岛呈现真实活动 → 结果自动成为有来源的结 → 在工作窗口里判断、修改、继续。

中途可以把现场收成卡片／图标，或中期放成外部小组件。再次展开恢复原 Focus、对话、供给和运行，不从零解释。

### 5.2 结、绳、剪保留为操作语言

- 拿起对象：结／棍，指材料、片段、产物和现场等可操作资产。
- 建立连接：把材料供给某现场，关联想法，或选择可运行路径。
- 断开连接：解除当前供给或关系；历史来路保留。

日常不必一直看到绳。拖入供给区、明确勾选、菜单断开和可视剪绳调用同一业务操作。节点焦点、V_b 可见集和工作现场 Focus 各有作用域，不能把“点开看看”当成“交给 Agent”。

### 5.3 移除材料与多轮连续性

用户移除 I2，就是剪断它与当前窗口的供给关系。下一次请求按新的可见集生成，旧 Session、摘要或来源链不能暗中带回 I2。必要时由适配器重建受控模型视图，人的对话现场保持连续。

已经发出的运行仍使用发送时快照，无法撤回已发送内容；用户可停止／重发。既不承诺模型“遗忘”，也不强制每轮新建会话。

### 5.4 主动性与低打扰

既有思想方案已有灵感卡、内部关系变化、Agent 自发生成、外部信息触发等主动来源。首轮保留接口与原生能力，优先低干扰地在灵动岛／角落入口呈现，而非不断插入用户正在写的内容。

自动整理不能覆盖人工固定、断开或隔离。主动建议的噪音、采纳与打扰程度作为后续验证项，不能把“主动”只衡量为消息数量。

## 6. 美学：OS 的熟悉感，Knot 的克制

既有设计依据包含 Apple 九弹索引、形式层规格、游戏交互调研与设计规范 v1。本轮是在这些依据上转译承载方式，不重新发明审美方向。

| 原有原则 | 工作站中的表达 | 落地边界 |
|-|-|-|
| 极致 Focus | 当前现场清晰，周边信息降低权重 | 聚焦不等于空白首页，也不删除其他工作 |
| 渐进披露 | 图标→卡片→窗口，关键状态→详细证据 | 状态与身份始终可辨认 |
| 低信息密度与留白 | 让工作内容主导，控件按需出现 | 不能为“干净”隐藏错误或待授权 |
| 非中心化与偏移 | 尊重桌面摆放、角落组件与多现场 | 不强迫所有东西回到一个永久居中聊天框 |
| 单一强调与中性色 | 延用暖橙、灰阶、克制边界 | 红色不同时混淆“当前”与“失败” |
| 动态有因果 | 收起、展开、转场帮助识别同一对象 | 不做无意义持续动画；支持减少动态 |
| 渐淡但不消失 | 低关注内容仍可找回 | 不自动删除资产或关键事实 |

旧规范的 4/8/12/16/24/32 间距级别、暖橙 `#ff9500` 可继续作为基础 token。旧画布节点固定尺寸、强制物理重排和“关闭即断全部绳”等不能直接搬到工作窗口。

排版、窗口宽度、HUD 避让、跨屏缩放和触达区通过原型验证后冻结。键盘操作、输入法、减少动效与非颜色状态提示是交互质量，不是最后补的装饰。

### 7.1 去重结论

重复主要发生在同一能力被换名重造，以及历史建议与冻结结论混读。此次撤回：新命令总线、新资产权威库、全新通用授权／委派体系、每轮强制新会话、未经对照的 Electron 定案与任意阈值。

保留的新工作：工作现场作用域、呈现实例、旧内核解耦、真实运行映射、精确输入验证、序列化增量，以及原生／设备适配。

今后新增任何能力，先查“已定方案—代码—测试—缺口”。找不到只记录“本轮未找到”，不直接宣布项目从未做过。

## 8. 协议与工程基线

### 8.1 已定的 Agent 原生基础

AGENT_FRIENDLY 要求全部语义状态数据层可达、每个操作有命令入口、变化可订阅、不同宿主可适配。UI 与 Agent 共用一个 Operation Kernel。

协议 v0.1 的最终冻结结果包括：快照／命令／SSE、写文件锁、seq 持久化、冷启动 snapshot 重置、共享 token 的初期访问控制与浏览器桥接过渡。沿用现有命令族与结果信封；新增现场／运行能力走版本化扩展。

### 8.2 五个工程边界

| 边界 | 负责什么 | 当前动作 |
|-|-|-|
| 资产／操作内核 | 结、块、绳、可见集、现场与一致操作 | 提取渲染依赖，扩展旧模型，契约先行 |
| 人的呈现 | 工作站、内部桌面、HUD、灵动岛、实例形态 | 消费同一状态，不各自存业务真相 |
| 运行适配 | DSH／Codex／Hermes 的执行、事件、回执、恢复 | 能力逐项核验；真实 Run 决定活动状态 |
| 开放接入 | 原命令协议、宿主与来源适配 | 保持薄适配，先复用后扩展 |
| 原生桌面桥 | 浮层、系统入口、捕捉、置前 | 中期窄探针后定具体容器，不提前绑死栈 |

旧 FlowGram 外壳不是新版主壳，但模型、OperationService、V_b、Bridge、provenance 与测试都是复用资产。当前内核仍依赖 document／linesManager，需要逐项解耦，不能一面声称可卸载画布，一面把运行真相继续锁在浏览器页。

DSH 已装不意味着要把资产事实源迁到 DSH KV。现有文件写回、快照、事件与运行附属状态分别明确权威，过渡期禁止双主写。

### 8.3 必守约束

真实模型入参必须符合当前可见集；旧历史回灌、工具越界回读、来源递归都要测。事件缺口按实际能力重置快照，不伪称无限回放。当前共享 token／Host source 不等于每 Agent 身份审计，读端点和开发默认凭据在对外部署前需要加固。

开发验证遵守服务层断言→程序化→用户人工过手。Maker／Checker 分离；分支与 PR，禁止自动合并。任务卡服务团队，不要求终端用户理解这些流程。

### 11.2 建议的最小人类团队（待落实，不是已批准编制）

基于当前缺口，优先凑齐 **产品／交互负责人＋两类工程主责＋独立核验能力**，按职责而非部门扩张。两类工程主责可由两人承担，也可由一位有余量的复合工程师阶段性覆盖；不能据此承诺同等并行速度。

| 岗位／职责 | 为什么现在需要 | 第一阶段要交什么 |
|-|-|-|
| 产品与交互负责人（之主导，设计协作者按需） | 统一 Focus、桌面层次、三态与审美，避免架构反向决定体验 | 一个真实场景、状态与动作表、工作站／外部实例原型、明确取舍 |
| 核心／集成工程主责（优先补） | 旧内核解耦、协议兼容、存储往返、真实 Harness、可靠性是主阻塞 | 基线报告、核心契约、DSH 探针、双端运行与恢复链 |
| 客户端／桌面交互工程主责 | OS 式窗口、HUD、灵动岛、焦点、输入法与原生桥接需要工程质量 | 可用工作站、同对象多呈现、状态正确的组件与原生能力验证 |
| 独立质量／可靠性主责（可兼职） | 避免 UI 像完成而协议／输入／恢复没跑通 | 契约测试、R1–R3、数据迁移／失联／越权回归、独立验收 |

招人时先看对应纵切能力：能否解释已有方案、复用一段内核、交付可复验结果，而不只看做过多少页面或接过多少模型。Agent 可以辅助调研、编码、测试与文档，但每条工作流仍需明确人类主责和独立验收方。

中期视实际工作量补系统集成／设备协议能力、用户研究与设计协作。首轮不必为模型训练、硬件、增长或生态运营设专职团队；这些不是当前主阻塞。此项是基于路线的团队建议，不是预算或招聘承诺。

每张卡含目标、旧方案出处、允许改动域、最小增量、产物、验证命令和 Checker。同一文件域避免同时写；不自动合并，不自我验收。之主要面对产品决定与体验，不替团队追逐全部日志。

## 12. 分几个阶段，各交什么

建议 **五阶段**。按证据过门，不复用旧文档中的半天／一周等估计冒充当前排期；人数和投入确认后再估时。工程细门 G0–G8 对应在开发方案中。

| 阶段 | 目标 | 必交付物 | 过门条件／主责 |
|-|-|-|-|
| 0 归拢与固定基线 | 清除重复、明确复用和真实起点 | 本总纲、复用表、代码差异与基线、能力矩阵、可运行测试清单、任务分工 | 方案与代码状态可对照；核心工程＋独立核验。文档已有，本阶段工程门未完成 |
| 1 可用工作站内核 | 用已有 AI 原生能力支撑新界面 | 兼容内核、现场／呈现实例增量、无损持久化、图标／文件夹、窗口三态、HUD、灵动岛、唤出器 | 人和 Agent 同效操作；不看画布也能工作；原现场恢复。核心＋客户端 |
| 2 真实协作闭环 | 工作站里真正接通 Agent | DSH 探针、稳定 Codex／Hermes 适配、索引、输入快照、Run／产物回执、R1–R3 报告 | 真实双端、准确输入、失联／取消／恢复可核对；独立 Checker 接受。集成主责 |
| 3 原生与已链接来源 | 在屏幕内外自由使用同一现场 | 外部浮窗／小组件、系统入口、Appshot、内部／外部实例切换、目录／NAS 限定接入 | 不分叉内容、不抢焦点、不越权、离线可恢复。桌面／集成主责 |
| 4 真实使用与创造迭代 | 验证用户愿意用、能持续创造 | 外部任务观察、主动协作与低打扰改进、拆分／嫁接缺口、模板样本、Jev 窄试点评估 | 能解释采用与放弃原因，核心价值有实例；产品／研究＋工程 |

用户验证从阶段 1 就开始，阶段 4 是集中收敛，不是到最后才见用户。Jev 在状态与候选动作稳定后可并行影子测试，但不阻塞真实运行闭环。

沿绳编排、复杂关系视图、决策时间轴、跨端连续性、模板生态和社区机制保留在长线池；每项按既有设计恢复与实现程度逐步进入，不能把长线池写成已承诺的近期功能列表。

### 12.1 所有阶段统一的完成标准

有来源、有实现或明确设计产物、有可复现验证、有独立验收、有文件地图与未决项。画面、代码存在、文档写了、命令零退出、协作卡完成，分别只证明各自范围，不能互相代替。

## 13. 下一步与真正未决项

可以立即推进：G0 当前代码／差异核对，G1 原内核契约与增量测试，G2 固定版 DSH 真实探针。先完成一个最小纵切，再扩到工作站与两端运行。

需要后续证据决定的事项：

- 哪个提交／独立工作树作为实施基线，如何保留当前未提交工作。
- 旧内核与新承载之间最小解耦接口，资产 schema 的兼容版本与恢复办法。
- DSH 客户端能承载哪些界面，运行端实际支持哪些能力；系统桌面宿主在窄验证后定。
- 人类工程主责、可用投入与独立核验安排；据此制定日历排期。
- 外部用户是否理解现场、供给、恢复与资产复用，以及在哪些任务上真正愿意持续使用。

不需要重开的问题：Knot 是否应 Agent 原生、是否共用操作内核、是否先查方案、是否保留人的理解与覆盖权。这些已有定案。
