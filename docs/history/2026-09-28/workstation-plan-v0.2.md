# Knot · Agent OS 工作台开发方案

v0.2 校正稿 · 2026-09-28  
用途：交给开发者进入分卡、适配与改造；原始定案与调研保留。  
状态：基于方案及当前代码的整理／工程建议，未实施、未运行回归，待独立 Checker 复核。  
本版替换本轮临时 v0.1；不覆盖共享层原文和旧交接包。

## 0. 人类层：现在定了什么

**Knot 的定义是 Agent OS 新范式，开发基线仍是工作台。**

它让人和 Agent 使用同一套可感知、可操作、可连接的资产环境。**工作站承担完整操作；桌面承担摆放、组织与随时取用，工作站内部也有自己的桌面。** 会话和文件夹既能留在里面，也能以外部浮窗／小组件呈现；深入操作时仍回到同一个工作现场。HUD 接受输入，灵动岛承接活动，角落小组件承接轻功能；占屏大小由用户选择。

画布弱化为按需的关系呈现。底层的结、绳、可见集、块生长和原生操作协议继续保留。界面简洁与 Agent 能力完整同时成立。

本次真正要改的是四件事：

1. **把旧画布承载中的业务能力解耦出来**，延续已定的 Operation Kernel、快照、命令与事件。
2. **把人的工作入口改成 OS 工作台**：窗口／卡片／图标、文件夹、HUD、灵动岛、角落小组件共用现场状态。
3. **补齐真实运行**：DSH 与外部 Harness 薄适配、稳定派工、原对话回填、产物来源与断绳后的输入更新。
4. **中期接原生桌面与已有来源**：系统悬浮／全屏切换、应用快照、已链接的本地 Agent／目录／NAS；沿用既有接入理念。

核心原则直接继承已有方案：**AI 用得爽，人类看得懂；自动织养，手动覆盖；数据层优先，所有入口共用操作内核。**

当前可先做 G0 基线核对、G1 内核兼容与 G2 运行探针。不需要之重新拍一遍已经定过的 AI 原生原则。只有找不到旧决策、证据冲突或涉及替换事实源的选择，才带方案差异交由之裁定。

## 2. 产品形态：工作台优先，关系按需

### 2.1 界面职责

| 入口 | 用户看到什么 | 对应底层能力 |
|-|-|-|
| 图标／文件夹 | 资产身份、项目组织、快速打开 | 同一资产 ID 与逻辑归属；不搬动物理文件 |
| 工作窗口 | 当前意图、对话／思考过程、产物、可继续的现场 | Focus＋对话／链＋可见集＋Run 引用 |
| 卡片／图标 | 同一现场的简化形态 | 呈现变换，不新建会话／资产 |
| HUD | 对当前现场说话，选择 Agent，查看本次供给 | 同一 Focus 的输入与命令入口 |
| 灵动岛 | 运行、等待、待授权、完成、错误 | 真实活动事件的紧凑投影；点击才展开细节 |
| 右上／右下小组件 | 轻功能、节点唤出、已固定现场、近期产物 | 功能入口或既有窗口的实时投影；位置可调整 |
| 悬浮唤出器／资源库 | 已有资产、工作现场、已链接来源 | 统一索引与接入器；被搜到不等于成为模型输入 |
| 按需关系视图 | 当前关注的连接、来源或可运行路径 | 同一结网的可视化；关闭后主功能保持可用 |

普通状态不要求拉满屏连线或维护画布。用户可以选择把会话、文件夹放在桌面，方便随时翻阅。拖入、勾选、菜单断开和可视剪绳操作同一业务关系。工作台与文件夹都能按需显示关系，不另建“画板系统”。

### 2.1.1 工作站、桌面与承载方式的层次

```text
工作站：完整操作、组织、编辑、协作与调度
  └─ 内部桌面：会话窗口、文件夹、图标、卡片
       └─ 同一对象可按用户选择呈现在工作站外
            ├─ 悬浮窗口：随时翻阅／恢复原现场
            └─ 小组件：紧凑呈现／快速打开
```

这不是三个互斥产品模式。工作站可以保持打开，同时有外部浮窗或小组件；用户也可以全部收回工作站内。详细操作由完整工作站解决，外部呈现优先翻阅、查看状态与打开原现场。是否允许某项轻编辑取决于该组件声明的能力，不能默认把完整工作站复制进每个小组件。

第一轮默认承载是工作站内部桌面；中期增加外部承载，不要求用户一定使用系统桌面。模型区分**对象身份**与**呈现实例**：每个实例记录同一 asset/worksite 引用、宿主位置、形态和布局。移出、收回、展开只改变呈现；关闭一个实例不删除对象，不取消运行。多实例编辑经同一命令内核与版本检查，避免形成两份内容。

是否全屏、置前或抢占输入焦点由用户动作决定。系统级入口与工作站内部入口复用原 Focus、对话和来源；从桌面翻阅后进入详细操作，不另开无关联会话。

“Knot OS”在本轮指 Agent 工作环境与交互范式；内核、驱动或替换系统桌面不属于当前实现范围。

### 2.2 Focus 与人的操作

- 复用 roadmap 中的 Focus：项目、意图、上下文、当前动作、预期产物；同时保留已有节点焦点。**节点焦点与工作现场 Focus 是两个作用域**，一次材料预览不能把 HUD 改投给其他任务。
- HUD 每次发送目标可见。切换窗口保存各自草稿、选定 Agent、供给和对话位置；后台运行仍归原窗口。
- 原有“勾选=V_b”是明确授权操作；普通视觉选择、查看和展开不等于勾选。新 UI 以供给徽标／HUD 清单表达相同语义。
- 文件／素材拖到桌面只建立节点或引用；拖入明确标识的窗口供给区才参与本次工作。对话产物自动成结，无需用户抄写保存。
- 窗口关闭只关闭呈现；断绳、停止运行、归档、删除分别执行。保持历史来源可追溯，不再沿用“红色关闭=断全部绳”的含混语义。
- 窗口、卡片、图标及现场小组件共享身份。图标化、归档、运行状态相互独立；有运行的图标保留活动入口。

### 2.3 自动织养与创造性

继承 v0.2 交互定案：Agent 在已授权的工作范围内自动整理、生长、维护信息结构，主动提供灵感与协作；人的拖拽、链接、隔离和断开是覆盖权。无需把每个低风险内部整理动作改成人工审批。

区分两类变化：

1. **组织／生成变化**：产物成结、归类、紧凑呈现、提供候选、已授权范围内续长。保留自动能力，并产生可检查事件。
2. **输入／权限边界变化**：外部材料进入某次运行、扩大设备范围、对外发送或写回。遵守当前 Focus 的选择、授权及外部动作规则，不能借“自动织养”越界。

人工断开的供给不能被整理过程悄悄接回。首次实现把该排除记录在当前 Focus，直到用户重连或明确重置；这是对已有手动覆盖权的落实。

创造性来自可继续生长、拆分、嫁接、比较和重组的资产。沿用已有命令和结内块，不把产品收窄成固定任务流水线。拆分／嫁接若只有设计而无实现，列为增量，不伪称现有命令已经覆盖。

### 3.1 架构目标

```text
人的入口：工作台／HUD／灵动岛／小组件
                         │
Agent 入口：已有 snapshot／command／events
                         │
           一个 Knot Operation Kernel
          模型、可见集、关系、工作现场
                         │
     资产持久化    Harness 适配    设备／来源适配    呈现决策适配
                  DSH / Codex / Hermes             Jev
```

DSH 是运行与宿主适配的候选基础，Knot 开放协议不依赖其私有 API。现有 HTTP 端点可以被 MCP 等宿主适配消费；业务命令、UI 声明、Agent 协作运输不是同一个层，不能互相替换。此前已选方案 C；A2UI／MCP Apps／A2A 的具体支持只在适配器交付并验证后登记。

### 3.2 最小可行迁移

1. 为当前内核建立契约测试，以现有服务层断言为基线；保留命令名、结果信封和旧资产 ID。
2. 把结网模型与业务操作从 `WorkflowDocument/linesManager` 依赖中逐项解耦。旧 FlowGram 保留兼容适配，新工作台调用同一内核；过渡期不得双主写。
3. 呈现切换、布局、节点焦点属于投影层；关系、V_b、块与真实 Run 映射属于数据／业务层。无关系视图时业务仍能运行。
4. 扩充既有序列化链，逐项验证命令→快照→写回→恢复。当前序列化器按白名单抽字段，直接往 data 塞字段会丢失。
5. 独立工作台／Headless 内核通过后，旧 Canvas Bridge 成为兼容通道；不能提前删除，也不能让中期后台运行依赖可见浏览器页活着。

过渡使用 FlowGram adapter 不等于把 FlowGram UI 重新定为主产品。具体源码落位在 G0 的独立实施分支确定，现有脏工作区保持只读。

## 4. 数据、协议与上下文：在已有契约上增量改造

### 4.1 新增数据最小集

以下是待版本化的**增量规格**，不宣称旧 schema 已支持。沿用 KnotNode／Block／Edge，避免新增平行 Asset 库。

| 增量 | 最少需要表达 | 落位原则 |
|-|-|-|
| 工作现场 | worksiteId、关联结／链、projectId、focusId、dialogueId、意图、预期产物、草稿、Agent 选择 | 扩展原模型；定义写回映射后再实现 |
| 可见集作用域 | 当前 Focus 选定结／块、人工排除、选定版本 | 复用 V_b，按窗口隔离；不得另一个选择服务各自写 |
| 呈现实例 | 实例 ID、原资产／现场引用、工作站内／外部宿主、窗口／卡片／图标／widget、位置、固定与占屏范围 | 多实例共用对象；可重建投影，不改变运行 |
| 关系角色 | 当前供给、普通引用、可运行路径、历史来源 | 沿用 edge 扩展及 provenance；旧边保持旧语义 |
| 输入快照 | focusId、revision、结／块 ID、版本与哈希、输入表示、prompt、Agent | 发送时不可变，作为执行证据 |
| 运行映射 | runId、adapter、外部 session／turn／job、快照引用、状态、cursor、回执 | 引用 Harness 事实，不复制执行引擎 |
| 来源连接 | connectorId、类型、授权 scope、能力、cursor、覆盖度、可用性 | 复用通用接入器思想；密钥另存 |

历史来源是事实，当前供给是可编辑关系。断开供给不改过去的 provenance。生成按已有“临时对象→正式块／资产”两阶段思路落地，失败和取消不能变成完成产物。

### 4.2 协议继承与必要扩展

沿用 `/snapshot`、`/command`、`/events` 和兼容 `/write`；保留 `knot.*`、`rope.*`、`chain.*`、`generate.*`、`tool.*`、`focus.set`、`expand.set`、`pin.toggle` 的已实现行为。

先查已有命令能否表达，再新增。工作现场 Focus、窗口恢复、真实 Run 启停等缺口通过版本化扩展补齐，不重命名一整套 QueryScene／ApplyCommand 协议。

- 当前写保护为文件锁；CAS 只是预留。新增 baseSeq／幂等 requestId 需版本、兼容测试与落盘方案，不假称已有原子事务。
- 当前事件为持久 seq＋内存缓冲；冷启动按已定全量 snapshot 重置。历史缺口／缓冲溢出回 snapshot，不承诺无限 SSE 重放。
- 共享 token 能做访问控制；当前 source 来自 Host 配置，不能区分共享 token 下的多个调用者。需要细粒度审计时再做身份升级。
- 读端点和开发默认 token 不应直接暴露给 NAS／局域网部署。部署前限定监听、补读鉴权、替换默认凭据；先加固原端点，不另建完整 RBAC 产品。
- UI／Agent 共用操作内核；新状态都有快照出口和事件。验证遵守已有服务层→程序化→人类过手阶梯。

资产事实源沿用原方案。DSH storage-domain 可评估用于自己的运行附属状态；本版不把 Knot 资产迁进去，不让文件写回与 DSH KV 各自成为权威。

### 4.3 剪断材料就是修改输入关系

用户从窗口供给中移除材料，或在关系视图剪断同一条绳。文件、其他窗口、过去运行均保留。

下一次请求根据当前 V_b／选定路径与人工排除生成快照；不能从旧 Session、自动摘要或上游 provenance 把已移除材料补回。来源展开、普通预览、图标选择不自动加入。

**保留多轮连续性，不规定每次发送都新建 Provider 会话。** 先验证适配器能否生成等价的当前模型视图；若某次缩减上下文无法在原 Session 安全实现，就在该变化边界重建受控上下文，UI 的 dialogueId 保持不变。继承历史片段／摘要作为带来源的可见内容管理。

已发出的 Run 使用发送时快照，断绳不能撤回已外发内容。界面可提示本次沿用旧快照并提供停止／重发。引入 K-02 只引入所选内容，不递归授权全部父输入；K-02 自身包含的文字属于明确选中的材料。

输入关系不等于文件系统沙箱。代码任务的 cwd／工具读写权限单独声明；验收同时检查模型请求和工具是否越界回读未选文件。

## 5. Runtime 改造：DSH 与外部 Harness

### 5.1 DSH 探针

固定当前安装版本，独立配置与插件源码，不改 `本机路径（node_modules）`。Headless 运行接入和客户端挂载分别验证，UI 构建问题不妨碍核对运行接口。

- 使用公开 Agent registry／Session 能力，映射 Knot runId 与外部 session／turn。`followup()` 返回 void，不是 runId。
- `whenIdle()` 表示整个 Agent 静止；成功要关联具体 turn 终态、取消／失败原因与真实产物。
- 流式字块用于展示，持久事件用于恢复；临时流、最终消息与产物回执分开。
- 无法独占关联的 Session 不混入多个不明来源请求。重连、取消、重复事件要有契约测试。
- 客户端需可加载的实际 bundle，复用前核对 React 与模块加载约束；装了包不代表可直接替换主界面。

接口边界经本地类型与 [DSH Core](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/core) 对照。`dsh-shell` 是命令执行接口，不是桌面悬浮窗口宿主。

### 5.2 外部派工沿用原 spec

Codex／Hermes 按已有派工层接入：读卡、边界、独立运行、产物回收、回执、日志、独立验收。保留执行生命周期脱离当前对话的要求，不以同 Harness 子代理冒充外部 Agent。

增量核验：启动、取消、恢复、输出、项目／会话索引分别声明 capability；独立 runId、快照、派发去重键、外部进程／Session 可对账。响应丢失先确认是否已接受，再决定重试；不无限重派。

页面关闭不杀已托管任务；Host 中断后恢复或明确报失联。重试沿用 spec 上限，且仅限确认可安全重试的失败。两个 Agent 同 Focus 并行，各自标来源；后续合成另有记录。`done_pending_check`／`closed` 沿用原卡协议，执行、呈现和验收状态分开。

“人2a2a”继承已有共用内核与开放接入设计。首轮不擅自新增通用委派树、硬编码委派深度／数量或另一套任务总线；具体协作通过原任务卡和适配器落实。

## 6. Jev、来源接入与原生桌面

### 6.1 Jev 窄试点

沿用已有研究，按之最新指认把窗口→卡片／图标排第一试点。候选由 Knot 提供，Jev 返回受约束选择，内核按当前状态执行；UI 渲染图标和卡片，原资产不变。

手动变形可立即使用；已启用的自动整理可自动执行；Jev 先做回放／影子模式，与原规则比较后决定是否替换决策来源。试点未验证不等于整个自动织养退回人工审批。

正在输入、固定、待授权、状态已变化等情形设守卫；旧 revision 结果丢弃。断网、超时回到原规则／保持原状。阈值、延迟和成本由回归数据决定，不把随手数字写成产品定案。

当前官方把 Jev 定义为文本状态上的类型化决策模型，不能替代截图理解、对话生成或真实状态判定；具体调用由独立适配器映射。[TypeSafe System One](https://docs.typesafe.ai/concepts/system-one)

### 6.2 资产唤出与设备

本地 Agent／NAS 节点化已在节点叙事与开放接入方案里；本版只安排适配、索引、版本与 UI 接入。

- 首轮：授权 Agent 项目／任务索引、既有资产唤出、显式文件引用；给出稳定 ID、来源入口、分页／增量、覆盖度和错误。
- 中期：已链接设备／目录／NAS。范围来自已有连接与明确选择，不自动扫描全盘或网段。
- 发现元数据与读正文分离；只有进入已授权工作路径才读取内容。掉线标不可用／快照时间，不把缓存当实时源。
- Appshot 保存来源、时间、图像及实际可读文字；先预览再进入工作路径。截图不证明 Agent 运行状态。
- 文本、语音、图片／视频、链接入口逐项登记真实能力。不支持的模态明示，不把文件名当已理解内容。

### 6.3 原生宿主

沿用“桌面桥／Knot 内核／运行适配”划分，不再画成 UI 必须穿过 DSH 才能到 Knot 的单向层级。置前、快捷唤出、窗口捕捉、原生浮层属于宿主端口。

先查已有接入与桌面调研，再做窄能力验证。Electron 可作候选，本版取消“已选 Electron”的定案；现有宿主能力不足、候选对比与授权范围明确后再冻结。无论何种实现，凭据不进 renderer、原生调用为窄接口、关闭浮层不结束真实运行。

原生验收：外部浮窗／小组件与内部桌面可同时存在；移出／收回不复制资产；深入操作恢复原现场；轻量呈现让出屏幕／输入，全屏可恢复；跨屏／缩放正确，快捷唤出不串 Focus，捕捉可拒绝，休眠重连可对账。

## 8. 首轮走查与质量门

### 8.1 三轮仍用同一窗口／Focus／对话

沿用原样本编号并冻结版本；新 UI 的供给／断开对齐原 V_b。

| 轮次 | 输入与操作 | 必须证明 |
|-|-|-|
| 初始 | 预览 K-01、N1，均未引入 | 输入为空；预览不等于选择 |
| R1 | I1/I2/I3，Codex＋Hermes | 两个 runId，同 F1／D1；分别有来源；指定真实输出为 K-02，不伪装共同结果 |
| R2 | 增加 I4，Codex 继续 | `{I1,I2,I3,I4}`，原现场连续，形成 K-03 |
| R3 | 断开 I2，供给 K-02，Hermes 继续 | `{I1,I3,I4,K-02}`，不递归拉回 I2；形成 K-04 |

K-03／K-04 自动成为资产，但默认不新增当前输入。N1 哨兵从不选择，最终请求和工具可见内容不得泄漏。R3 历史检查用未包含在 K-02 的 I2 专属标记，避免把主动选中的结果误判为泄漏。

### 8.2 必测与证据

- UI／协议对同一结操作，结果与事件一致；新状态数据层可读，无 UI 模拟依赖。
- blocks／provenance／edges／fixed 与工作现场字段往返无损；三态不改身份。
- 内部桌面与外部浮窗／小组件引用同一对象；移出、翻阅、深入操作、收回无内容分叉；关闭呈现不取消 Run。
- 关闭关系视图，供给、对话、运行、产物和继续工作均可完成。
- 自动产物成结／整理生效；人工断开、固定、隔离不被自动化覆盖。
- 快照对应实际请求；旧 Session／摘要／工具读取不越过本轮边界。
- 真开始才显示 running，终态有来源；两个 Agent 不混结果；usage 与 token 估算分栏。
- 重复事件不重复产物；冷启动／回放缺口按 snapshot 重置；派发回执丢失先对账。
- 文件锁与认证有效；新增来源不越授权路径；密钥不入资产／日志／renderer。
- 原生阶段验证占屏、焦点、捕捉拒绝、离线恢复；Jev 失效仍能完成主线。

证据包含代码基线、环境、实际命令与退出码、快照哈希、Run／Session／turn 对应、结果来源、失败及未覆盖项。人类层只看“定了什么／需你决定什么／下一步”，全量证据留执行层。Maker 提交候选、Checker 独立接受；遵守现有分支、PR、禁止自动合并纪律。
