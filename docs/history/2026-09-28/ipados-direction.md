# knot 定调 · iPadOS 对标（2026-09-28 · 之定）

> 来源：之 2026-09-28 桌面端原话（其称之为「非常重要」）
> 处理：**原话逐字**（不改一字）+ 理解映射 + 画板定位推测（推断层，标注待确认）

## 一、原话（逐字）

「基本出来了，我们直接对标ipad os就可以了，线性工作流直接对标ipad os的台前调度，卡片的形式在里面，只需要有这些东西就可以，语义空间就是app资源库，这样说你能懂吗。因为实际上一个窗口等于一个app更符合我们的逻辑，非常符合，这就是资产节点化，为什么没有人把harness软件做成这样的东西呢，我把窗口塞到文件夹里不就是项目文件夹吗，图形化很重要啊，你先记下来我这段话这非常重要，至于画板的定位你也可以合理推测一波，我已经给了你一个很明确的方向了」

追加原话（同日）：「是的基本就是直接对标mac os ipad os ios了。全面对标，，我要是小窗口的话我就让他对标iwatch os」

## 二、对标映射（理解）

| knot 概念 | iPadOS 对标 | 含义 |
|---|---|---|
| 线性工作流 | **台前调度（Stage Manager）** | 正在干的现场=前台；其他=后台卡组 |
| 卡片 | 窗口（Window） | 每张卡=一个窗口 |
| **窗口 = App** | App | **一个窗口 = 一个 app**（独立身份 / 任务 / 资产） |
| 语义空间 | **App 资源库（App Library）** | 资产节点化的**自动归类 / 聚合 / 检索**层 |
| 窗口塞进文件夹 | Files 文件夹 | **= 项目文件夹** |
| 图形化 | —— | **图形化很重要**（UI 层是核心竞争力） |
| **全面对标** | macOS / iPadOS / iOS | 「直接对标mac os ipad os ios了。**全面对标**」（追加原话） |
| **小窗口尺度** | **watchOS** | 「我要是小窗口的话我就让他对标iwatch os」——窗口越小，对标越微型化的 OS |

**尺度 → 对标（整理）**：桌面全屏 = macOS｜工作现场（主）= iPadOS｜小单元 = iOS｜微/组件 = watchOS——**每个窗口尺度都有对照，统一在 Apple 全生态的交互语言里**。

**核心洞察（之原话）**：
- 「一个窗口等于一个 app 更符合我们的逻辑，**非常符合**——**这就是资产节点化**」
- 「**我把窗口塞到文件夹里不就是项目文件夹吗**」
- 「**为什么没有人把 harness 软件做成这样的东西呢**」——这是独特位（现有 harness 都困在聊天侧栏/IDE 形态）

**为什么没人做（理解）**：现有 harness（Cursor / Codex GUI / 各类 Agent 客户端）都服务「一个任务、一个聊天栏」；knot 服务「一个人全部的思考与工作」——**服务对象是「一个人」，形态就得是 OS 级（窗口 / 文件夹 / 资源库），而不是面板级**。

## 三、画板（Canvas）定位 · 合理推测（推断层 · 待之确认）

在 iPadOS 坐标系里推：
- **主推**：**画板 = 打开的项目文件夹（夹层视图）**——窗口（= app = 工作现场）塞进文件夹后，**打开文件夹**看到的 = 节点与连接的空间（画板）；即：**文件夹 = 组织单位，画板 = 它的展开形态**。
- **配套**：**资源库（语义空间）** = **跨项目的自动归类层**（浏览）；**画板** = **可编辑的组织层**（连线 / 打结 / 重组）。
- **备选**：画板 = 资源库的「编辑模式」（浏览看资源库，重组进画板）——与主推可合并：**资源库（浏览）→ 画板（编辑）**。
- **三件套结构（推测）**：**台前调度（正在做的）｜文件夹 / 画板（按项目组织的）｜资源库（全资产语义浏览的）**
