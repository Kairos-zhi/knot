# knot 编排层可借鉴清单（源自扣子 Coze 工作流）

> 2026-08-29 晚 · Oracle 提到字节扣子 → 调研 → 之定「核心=工作流编排（节点+连线）拿来用」
> 源：扣子四万字教程（coze_工作流节点指南.md，本地）+ 官方文档 www.coze.cn/open/docs
> 对齐：定位纲领「信息只沿用户指定的绳结流经产物节点」= 这句话的执行层

## 一、扣子工作流核心机制（抓到的）

1. **强制闭环**：开始节点（用户输入）→ 处理节点 → 结束节点（输出）；必须指向结束节点才能试运行/发布
2. **节点类型体系**：大模型/代码/消息/数据库/选择器（条件分支）/图像流/知识库/插件
3. **参数两分**：输入参数分「引用」（取前面节点的值）和「输入」（自定义值）——数据沿连线流
4. **验证流程**：先试运行（可单节点测），无误才发布
5. **对话历史开关**：大模型节点可启用「Bot 对话历史」——把历史作为数据再次输入（上下文注入）
6. **输出格式**：文本 / Markdown / JSON
7. **结束节点两种回答模式**：返回变量由 Bot 生成回答 / 直接按设定内容回答
8. **已知限制**：不支持真正循环，只能有限迭代的线性工作流

## 二、映射到 knot 编排层

| 扣子机制 | knot 对应 | 说明 |
|---|---|---|
| 开始/结束节点闭环 | 绳的起点终点：对话发起=开始结，产物落定=结束结 | 绳不再只是关联，是可运行路径 |
| 节点类型体系 | 结型体系：大模型=对话结，代码=工具结，选择器=决策结（分支），知识库=检索结（招魂），插件=外部轮子 | 8 种结型天然对应 |
| 引用/输入参数 | 绳上流产物（引用）+ 上下文（输入） | 「信息沿绳流经产物节点」的工程化 |
| 试运行→发布 | 结的生长态验证：雏形→试运行→成型（对应极乐迪斯科内化进度） | 与形式层「结的生长态」打通 |
| 对话历史注入 | 勾选=上下文（已有 D2） | 扣子用开关，knot 用勾选+语义簇 |
| 输出格式 | 产物节点格式意识（文本/MD/JSON） | 产物资产化前的格式约定 |

## 三、差异点 = knot 的机会

1. **扣子不支持真循环，knot 天然可以**：结网+语义场支持回溯/迭代/循环引用——「沿绳循环」（回顾-迭代-再打结）是 knot 相对扣子的结构性优势
2. **扣子编的是任务流，knot 编的是对话资产流**：节点里跑的是产物/上下文/token，不是任务单——不会滑成 Dify/扣子
3. **扣子画布是空白的，knot 画布是长出来的**：结是对话自动长的，编排是在已有结构上牵绳——先有网，后有流
