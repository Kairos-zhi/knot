# 对标：采用什么，怎样转译

更新：2026-10-18。基于既有研究与产品澄清归并；本页不新增竞品排名、性能、成本或“市场空白”事实。

## Apple 系统范式的转译

| 参照 | Knot 的设计采用 | 工程／体验约束 | 当前实现程度 |
|---|---|---|---|
| 台前调度 | 切换可恢复的工作现场，当前焦点清楚 | 不暗中合并现场上下文 | 现场数据已有；完整切换界面待做 |
| 窗口／App | 有稳定身份的会话与工作对象 | 对象与呈现实例分离 | window／card／icon 引用模型已有 |
| 文件夹 | 项目组织与随时取用 | 组织不自动成为模型输入 | 完整项目文件夹体验待做 |
| 资源库 | 跨项目的资产查找、聚合与唤出 | 搜到／预览不等于授权全文 | 统一索引与来源适配待补 |
| 灵动岛／活动摘要 | 工作岛只呈现真实活跃任务与返回入口 | 状态来自 Run，完成／失败／待授权可辨认 | 运行接入与组件待集成 |
| 不同系统／设备尺度 | 工作站、浮窗、卡片、微组件分配信息密度 | 多实例共享对象，轻入口可回详细现场 | 原生宿主尚未冻结 |
| Handoff／连续性 | 切走再回原工作，跨承载不丢身份 | 不能用缓存／动画伪称同步与恢复 | 本地恢复通过；跨端未验收 |

Apple 提供熟悉的组织与表达参照，不替 Knot 决定资产、供给或 Agent 权限。小组件并非独立资产库，画布也不拥有另一个工作现场内核。

## 其他研究线的取用

| 研究线 | 保留的贡献 | 限制与修正 |
|---|---|---|
| Agent 原生／开放接入 | Read／Write／Protocol、唯一内核、宿主薄适配 | 外部标准分层适配，未验证不标兼容 |
| Coze 编排 | 输入引用、节点试运行、输出与产物闭环 | 沿绳执行后置；不沿用历史厂商限制作为今日结论 |
| Cola | 块、生长、可见集与可解码压缩的区分 | 不是 Knot 已采用的模型架构；不要求首轮训练模型 |
| 游戏表达 | 线索、展开、聚合、可见焦点、未知与使用痕迹 | 空间表达按新承载转译，不能让画布成为主线前提 |
| DSH | Agent／Session／turn／事件的运行承载 | 当前仅外部单次候选，未形成产品闭环 |
| Jev | 从有限状态和候选动作中辅助选择 | 首试窗口→卡片／图标；先回放／影子评估，不替代状态或长文本生成 |
| 协作与信息处理实践 | 既查、派卡、回执、独立核验、双层交付 | 团队流程不直接塞进用户每次操作，不另造任务总线 |

Jev 试点要对照既有规则、守卫人工固定／输入中／待授权、丢弃过期 revision，并有超时降级。窗口成为图标不等于归档；旧推演将两者混写的部分已校正。

## 同类产品如何比较

聊天、编程 Agent、白板、知识库与流程编排是不同使用入口，Knot 需要用真实任务检验跨材料、连续现场和资产复用是否有价值。历史“它们只有聊天框”“别人都没有”“token 必降”的表达不作为现行事实。

后续比较至少注明版本／日期、目标用户、输入权限、运行可观测性、产物复用、恢复与退出成本；每项给实际观察或一手来源。研究结论进入功能前还要有对应实现与验收。
