## 职责与当前事实

DSH 或外部 Harness 承载 Agent、Session、turn、工具和实际执行。Knot 持有用户现场、准确供给、呈现与运行关联。桌面宿主提供系统级入口和捕捉端口。

本仓库当前请求适配仅调用注入的本地 receiver，生成服务仍为 mock。它没有内置 DSH Provider、真实 Session、Codex／Hermes 运输或 Run 管理。

已有独立工作区在固定 DSH `0.1.7-rc.2` 上完成一次真实模型请求：终态 completed、一次 Provider／HTTP 请求、零工具与辅助模型调用，返回探针标记。该候选仍待其独立 Checker，源码与运行记录不在本仓库。此事实只证明窄探针，不证明完整 G2、双端、恢复或产品完成。

## 一次 Run 至少要对上什么

| Knot 侧 | 外部执行侧／证据 |
|---|---|
| runId、现场／对话身份 | adapter、外部 Session／job／turn |
| 发送时输入证据 | 实际请求文本／材料与工具权限 |
| 事件 cursor 与真实状态 | turn start／end、seq、持久事件 |
| 成功／失败／取消／失联 | 明确终态原因，不只等待“空闲” |
| 产物引用与 provenance | 实际产物内容／哈希和来源 |
| 重连与重试决定 | 已接受／已执行对账，去重与回收 |

固定探针所用接口中 `followup()` 返回 void，不能当作 runId；`whenIdle()` 是整个 Agent 静止，不单独证明指定 turn 成功。持久终态和产物是独立证据。

## 外部 Agent 接入

沿用任务、认领、执行、回收、回执与独立验收的既有方法。对每个适配器分别声明项目／会话索引、启动、取消、恢复、输出与状态能力。不以同一 Harness 内的子代理冒充真实外部 Codex 或 Hermes。

同一 Focus 下的两端运行各有 runId 与来源；两份结果分别存在，后续合成另留记录。对话或页面关闭不应杀已托管任务；宿主退出后可恢复或明确标失联。未知是否接受时先对账，不能无条件重派有副作用的动作。

## 上下文与工具

按发送时当前供给构建实际模型视图。人工排除不能通过旧 Session、摘要或工具重新带入。必要时重建受控上下文，但不强制每轮新会话；界面 dialogue 连续性与 Provider Session 策略分开。

模型输入选择不是文件系统沙箱。cwd、目录范围、工具允许读写与外发权限单独声明，验收同时看请求和工具轨迹。
