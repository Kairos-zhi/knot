# Knot：把一次次思考，留成能继续工作的现场

Knot 是 Agent OS 新范式，当前以工作站实现。它面向使用 AI 做研究、策划、写作、设计与开发的人：让材料找得到，想法接得上，Agent 的工作看得清，产物能再次使用。它追求极致聚焦、优雅交互和便捷连接：连接让思考继续生长，思考成为可复用资产，人和 Agent 在同一现场共建。

你打开一个项目，进入一个工作现场，明确选择这次要用的材料。Agent 执行后，结果留下来源，成为下一轮可以引用的资产。你可以补材料、移除材料、换一个 Agent，也可以切走再回来。

## 长什么样

完整工作站负责详细操作。里面有桌面、项目文件夹、会话窗口、卡片与图标；HUD 是当前现场的输入栏，工作岛显示进行中的活动。关系视图按需出现。

同一会话或文件夹以后也可以放到系统桌面的浮窗或小组件里。内部窗口、外部组件引用同一个对象，深入工作时恢复原现场。占多少屏幕由用户选择。

## 为什么这样做

对话不只是一串消息，还可以积累成带来源、能重组的资产。人用直接操作表达“看什么、用什么、连什么”；Agent 用数据和命令参与同一个环境。已授权范围内的整理和生成可以自动发生，人始终可以固定、断开和修改。关系可以像活结一样重选、断开和重新组合，来路仍然保留。

结型表达的是路径、关联或待拆的问题等语义，不等于权限。读、写和 Agent 使用分别由供给范围、目标操作、调用者身份与授权策略校验；视觉上的连接、选中或展开都不能单独扩大权限。

Apple 的台前调度、窗口、文件夹和活动状态提供熟悉的交互参照；Knot 具体解决的是工作现场、资产连接与 Agent 协作。采用关系见[对标结论](../research/comparisons.md)。

## 当前进度与协作机会

主分支已具备现场隔离／保存恢复、输入编译、本地请求适配和兼容桥接。新版工作站和产品内真实双 Agent 连续协作仍在后续开发范围，当前界面中的生成服务仍为 mock。

现在需要补齐核心／运行集成、客户端交互和独立核验职责。协作者可以从已有代码与测试接手一个完整小交付，见[团队与入场](../development/team.md)。角色需求不代表人员已经到岗，也不构成日期或产能承诺。
