# 路线图

更新：2026-10-18。继承 9 月总纲和开发方案的五阶段／G0–G8，不重新建立另一套路线。日期是状态核对时间，不是各功能的交付承诺。

## 五阶段：每段拿到什么

| 阶段 | 目标与交付 | 过门条件 | 当前状态 |
|---|---|---|---|
| 0 归拢与基线 | 产品／工程文档、来源、差异、可运行测试与分工 | 起点可复建，决定和事实可对照 | 代码基线与九项复测已有；本 PR 补产品知识，人员／体验决定仍待落实 |
| 1 可用工作站内核 | 兼容操作、现场状态、无损恢复；图标／文件夹、三态、HUD、工作岛 | 同一对象、操作同效、无关系视图也可工作 | 现场与输入／请求底层三段已合入；完整 UI、内核进一步解耦仍未交付 |
| 2 真实协作闭环 | DSH、稳定 Codex／Hermes 接入、索引、输入与 Run／产物证据 | 真实双端连续三轮，取消、失联、恢复可对账，独立接受 | DSH 单次候选跑通，待其 Checker；其余不能算通过 |
| 3 原生与已链接来源 | 外部浮窗／组件、系统入口、Appshot、目录／NAS | 同对象不分叉、权限与离线行为真实 | 方向与边界已有，尚无本次交付证据 |
| 4 真实使用与创造迭代 | 用户观察、主动协作、模板、拆分／嫁接缺口、Jev 试点 | 解释采用／放弃原因，核心价值有真实实例 | 后续按实际使用推进，不是已承诺功能总表 |

用户从阶段 1 开始过手，阶段 4 集中收敛；不是到最后才见用户。近期按实际人手滚动安排，不能沿用历史“半天／一周”等估算。

## 工程门：怎样判断做成

| 门 | 范围 | 必须保留的证据 |
|---|---|---|
| G0 基线 | 提交、差异、依赖、命令与实施位置 | 可复建对象、原改动保护、未测项 |
| G1 内核与数据 | 共用操作、现场、呈现、序列化与解耦 | 人／Agent 等效、新旧数据往返、无第二个资产权威 |
| G2 运行探针 | DSH 真实输入、终态、取消与恢复，客户端挂载另测 | Run／Session／turn 关联；单成功例不包办全部故障路径 |
| G3 工作站 | 文件夹、三态、HUD、工作岛、唤出 | 正确目标、供给、状态与现场恢复，用户可理解 |
| G4 稳定两端 | Codex／Hermes 派工、索引、回填、重连与去重 | 两端独立 Run、权限与产物、失联先对账 |
| G5 首轮闭环 | R1–R3、哨兵、协议与 UI 等价、冲突回归 | 技术独立核验及人的体验判断 |
| G6 Jev | 窗口呈现窄试点、规则对照与影子回放 | 故障可降级、不改变运行事实、决策有数据 |
| G7 原生与设备 | 浮窗、Appshot、授权来源／NAS | 身份与权限不分叉，焦点与离线正确 |
| G8 关系增强 | 显线、剪线、复杂链检查与逐步编排 | 同一协议，关闭关系视图不阻塞主线 |

G1/G2 边界明确后可并行；G3 交互可先用标明的 fixture，再接真状态；G4 不必等待系统浮窗。G5 是首轮闭环的验收门。现在不能把 W3-A 三段接受等同于 G1 全部完成，更不能判 G5 已过。

## 下一段的实际顺序

1. 以已合并 main 固定开发起点，独立核验已冻结的 DSH 单次运行证据；不为文档整理再发模型请求。
2. 明确运行适配契约，完成一个现场的输入→真实运行→终态→正式产物；补取消与失败。
3. 客户端并行做最小工作站交互，用同一现场与操作入口接入真实状态。
4. 接入两端运行、原对话回填、恢复与去重，再跑完整三轮和体验走查。
5. 在稳定对象／运行基础上扩展原生入口、来源与 Jev。

工程近期任务见[W0–W6 计划](../development/plan.md)。真实使用场景、首轮范围取舍、可用工时／预算、评审节奏仍按人的实际决定登记，不由历史文档代填。

## 保留的长线与已撤回方案

沿绳编排、语义重组、跨端连续性、模板与社区保持长线。Electron 尚未冻结；不强制每轮新 Session，不把 DSH KV 设为资产权威，不另建通用委派树或整套命令总线。

早期路线及完整历史候选见[历史索引](../history/README.md)，当前采用／撤回依据见[决策演变](../history/decisions.md)。
