## 可以继承什么

| 维度 | 已有设计材料 | 新工作站如何使用 |
|---|---|---|
| 强调色 | #ff9500 及中性灰、状态色与标签纸研究 | 一个主要强调语义；状态不能只靠颜色 |
| 间距 | 4／8／12／16／24／32／48 的旧阶梯 | 作为组件密度候选，按窗口／HUD／组件尺寸复验 |
| 圆角与材质 | 多级圆角、描边、低对比阴影和玻璃表面 | 保持层次与可读性，不为模糊牺牲正文 |
| 字体 | 标题／正文／元信息层级 | 新工作站需验证中文、缩放、长内容及输入法 |
| 动效 | 旧快／中／慢、折叠、生长与回馈参数 | 状态先提交；减少动态效果下保留等价信息 |
| 图标与快捷键 | 旧展开、绳孔、棍绳剪和键盘映射 | 根据真实动作重验，不让同一符号代表多个生命期动作 |

这些是既有 Knot 设计候选值，不是 Apple 对所有平台统一规定的常数。旧卡片的 240px 宽、16px 触控区、焦点物理布局与固定坐标，不能直接套给工作站窗口或外部小组件。

## 当前组件规格需要补齐什么

窗口／卡片／图标、文件夹、供给区、HUD、工作岛、唤出器与角落组件，应分别写目标、状态、操作、焦点、键盘、来源和恢复规则。每个状态绑定真实数据，fixture 标记清楚。

目前 Workspace 保存 window／card／icon 及 layout；尚无完整原生 widget 宿主字段。组件设计不能通过新增私有 UI store 绕开模型边界。

## 验证顺序

先过[交互动作表](../product/interaction.md)和单一真实场景，再确认层次、密度、字体与 token，最后检查动效和原生尺度。使用者看不懂目标或供给时，回到交互决定层修正，不能只继续抛光样式。

现行验收见[开发验收](../development/acceptance.md)。旧规格的历史完成标记、阈值和建议，不直接证明当前工作站已实现。
