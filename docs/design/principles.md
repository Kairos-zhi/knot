# 设计原则

更新：2026-10-18。沿用产品总纲的 OS 熟悉感与 Knot 的克制；研究如何采用见[对标结论](../research/comparisons.md)。

## 工作在前，工具在后

主屏让人清楚当前在做什么、用什么、Agent 是否在执行、结果在哪里。工具与运行细节按需展开，不把主屏做成常驻控制台。一个人可以有多个现场，当前焦点应明确且能回去。

留白服务理解，不等于完全没有信息。可读性、焦点和真实状态优先于毛玻璃、光晕或空间氛围。

## 熟悉的对象与动作

文件夹组织项目，图标识别对象，窗口承载详细工作，卡片保留可恢复现场。输入、收起、关闭、断开、停止与删除的语义分别清楚。

采用 Apple 系统范式时转译工作语义，不机械复刻外观或所有菜单。旧卡片的红绿灯、尺寸和焦点重排不能直接冻结成新 OS 工作站的全部行为。

## 克制的表达

低信息密度、留白、单一主要强调、清楚的主次与渐进披露沿用既有方向。色彩、材质、动效都应说明状态或帮助定位，不依赖连续动画制造“正在工作”的假象。

错误可以安静，但必须可理解、可回看、可处理。历史“错误沉默”不能用来掩盖运行失败、输入被拒绝或保存失败。

## 连续性与覆盖权

状态先可靠，动画再增强。窗口换形态或暂时隐藏，资产身份和运行归属不变。自动整理保留主动性，人可以固定、断开和重排。

视觉上选中一个东西，与授权将其交给 Agent 是不同动作；供给范围、目标现场和外部读取必须清楚。

## 无障碍与多种输入

键盘／点击提供手势等价路径；焦点清楚；缩放和减少动态效果后仍能完成工作；颜色不是唯一状态信号。微型组件可以减少内容，但不能把错误与授权状态缩成不可理解的装饰。

先在一条真实工作路径验证，再扩展尺寸、跨屏与原生入口。设计参数与宿主、字体和输入方式共同测试，见[设计系统](system.md)。
