# 工作站失败与恢复

028已独立限定接受，范围见[任务卡](../tasks/KONT-WORKSTATION-028.md)。本页描述客户端恢复约束，后端仍沿用既有workspace读取/命令接口和revision并发检查。在用桌面尚未更新。

workspace请求失败时，只显示本地固定文案，不显示服务message、网络异常原文或响应正文。HTTP 409与既有STALE_REVISION组合表示现场版本冲突；401/403提示连接拒绝。其余失败按读取或写入区分：写入响应丢失、无法解析或请求报错，不能证明命令未落盘，因此提示刷新核对。

失败保留已知现场快照和本页草稿。错误尚未解除时阻止提交，刷新与返回对话保持可用，草稿仍可编辑。不会自动刷新、重发POST或重放创建材料/现场等动作。状态栏在错误期间不表示保存成功。

用户手动刷新只发送读取请求；成功后才允许再次提交，失败继续保留屏障。刷新保留各现场的本页草稿，不把其他现场的草稿迁入当前现场。之后显式保存使用最新revision；保存期间追加的文字不被旧回执清除。刷新尚未结束时，状态栏使用中性核对提示。

刷新不是未知写入的幂等回执：需核对当前数据再决定是否重复动作。此机制不提供跨应用重启草稿恢复、删除现场的草稿恢复界面、完整命令幂等记录或持久Session恢复。浏览器布局、人的体验和在用桌面部署需后续验证。

维护入口在packages/dsh-plugin/src/client.cjs的workspace api、refresh与mutate，仍共用026预览失效机制。专项测试tests/workspace-recovery-client.test.mjs通过真实built factory/组件回调和hook接缝验证；程序化语义检查不代表实际浏览器体验。
