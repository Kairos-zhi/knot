# KONT / Knot 开发约束

开发前必读 [开发基准与工作流](docs/development-baseline.md)，以及其中登记的既有产品、架构、协议、设计来源。当前执行入口为仓库上层 [STATE.md](../STATE.md) / [QUEUE.md](../QUEUE.md)；本模块的历史任务文档保留当时范围。本文补充上级治理，不替代 Maker／Checker 分离和合并授权。

- 之于 2026-10-21 明确：**后端对齐竞对，前端对齐 Apple。** 这是后续开发约束，不是待重新确认的建议。
- 后端先查竞品成熟机制与已有 Knot 代码、协议、测试，写明复用／适配／补缺及依据；不把研究建议自动当成已批准任务。
- 前端按 Apple 系统交互对标窗口、文件夹、台前调度、资源库、渐进披露和连续性；遵守已有 Knot 设计基准，不随意另定色彩与产品形态。
- 人和 Agent 共用对象、操作内核与业务语义；状态可读、动作可调用、变化可订阅，接入保持宿主无关。
- 数据与操作契约先于 UI。禁止用截图、模拟点击作为 Agent 开发／验证 Knot 的路径；优先服务层，再程序化检查，人的体验由之过手。
- 每个任务沿用既查 → 受理／拆卡 → Maker → 自核验 → 独立 Checker → Gate → 入档／收口；不得自验收或自动合并。
- 2026-10-21 用户授权“移交中控，开工”后，执行入口为根 `STATE.md`／`QUEUE.md` 与任务卡。首卡 `KONT-KERNEL-001-r2` 已独立限定接受，范围仅为 Headless 兼容纵切及窄修复；不据此接受完整产品或继续扩写原表单界面。最新任务与边界以中控状态为准。
