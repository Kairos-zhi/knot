# knot agent 原生友好标准（开发基石 · 宪法级）

> 定案：2026-08-30 · 之
> 地位：knot 一切开发的基石约束。每次开发/派单/审计必须遵守，违反即返工。

## 一句话标准

**knot 之于 agent，像 fs 之于程序、HTTP 之于服务——是基础设施，不是工具。**

## 三条硬标准

### ① 原生感知（Read）
agent 能以**原生状态**读取工作台——结、绳、资产、链、簇的状态**全部数据层可达**。
- 禁止：要求 agent 用 UI 截图、DOM 模拟、坐标点击来"看"画布
- 要求：任何状态都有数据出口（JSON/API/事件流），agent 读数据即知全貌

### ② 原生调度（Write）
agent 能以**原生状态**操作工作台——打结、串绳、续长、拆分、嫁接=**命令协议**，发命令即执行。
- 禁止：操作只有 DOM 事件一条路（agent 模拟点击）
- 要求：每个操作都有命令接口（addNode / connectLine / growBlock / splitChain / graft…），UI 手势与 agent 命令走**同一套操作内核**

### ③ 完全兼容（Protocol）
不同 agent 软件（Claude / Codex / Hermes / 未来任何）通过**开放协议**接入，零特判。
- 要求：协议是开放标准（MCP / HTTP / SDK / 事件流），与具体 agent 实现解耦

## 接口分层（"接口分很多种"）

| 层 | 接口 | 消费者 | 形态 |
|---|---|---|---|
| 人机接口 | 手势/红绿灯/工具条/漏斗卡片 | 人 | UI 事件 → 操作内核 |
| agent 程序接口 | A2A 命令协议 | agent | 命令/事件 → 操作内核 |
| 数据资产接口 | 资产清单/写回/双向同步 | 人+agent | JSON 文件 + 写回服务 |
| 协议接口 | 跨 agent 通信/多项目穿透 | agent×agent | 开放协议（后定） |

**核心原则：所有接口共享同一个操作内核（Operation Kernel）**——UI 和 agent 操作的是同一份语义空间，不是两套逻辑。

## 开发红线

1. 新功能必须先有**数据模型**再有 UI（数据层优先，UI 是投影）
2. 任何 UI 操作必须对应一个**可程序化调用的操作函数**（未来命令协议的直接候选）
3. 状态变化必须可订阅（事件流），agent 能监听工作台的任何变化
4. 禁止把业务逻辑写死在组件里（组件=视图，操作=内核，资产=数据）
5. 新增接口类型时，先想清楚四层里它属于哪一层

## 当前差距（Checker 审计基线）

- ✅ 数据资产接口：asset-sync/asset-persistence 已有雏形
- ⚠️ 操作内核：操作散落在组件/插件里（render.tsx 的续长、rope-tool-plugin 的串绳），未收敛为内核
- ❌ agent 程序接口：完全空白（只有 DOM 事件）
- ❌ 协议接口：未设计
