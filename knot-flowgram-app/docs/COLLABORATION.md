# knot 开发协作范式

> 用 knot 的方式开发 knot——决策成结，任务成链，进度成资产。
> 本范式是 knot 自身逻辑在开发过程中的 dogfood：我们怎么建 knot，就是 knot 将来怎么被用。

## 一、参与者与角色

| 角色 | 人 | 职责 |
|---|---|---|
| 拍板人（决策） | 之、杜 | 产品/战略/技术决策拍板；规格验收 |
| 实现（Maker） | 小禾、杜的 agent | 按规格实现，只碰自己的文件边界 |
| 评审（Checker） | 小禾（中控） | 合并前验证：tsc + 浏览器实测；证据留档 |
| 资产落账 | 小禾 | 决策/产物/进度落资产（内容包/资产清单/接力卡） |

原则：**拍板是人的事，实现是 agent 的事，验证是独立的事**（Maker/Checker 分离，不自评自合）。

## 二、协作循环（一个迭代）

```
1. 对谈（之×杜×双方 agent，每周）→ 决策
2. 决策落资产（内容包「范式定案」/飞书协作文档 → 资产清单）
3. 规格先行（调研 → 规格文档 → 拍板 → 标注「可派」）
4. 任务分派（按规格拆任务，每个任务：目标 + 规格依据 + 文件边界）
5. 实现（各带各的 agent，遵守文件边界，不碰 git）
6. 合并评审（中控统一验证：tsc + 浏览器实测 + 单次提交）
7. 交接（接力卡 + activity-log 落账）→ 下一轮
```

### 关键动作的固定姿势

- **规格先行**：任何实现前先有规格文档（形式层规格 v1 就是模板：调研 → 取舍表 → 拍板 → 可派）。规格里必须写：依据、取舍、验收标准。
- **文件边界**：分派时写死每个任务的目录边界（参考 `阶段2_dispatch/`），实现者不越界，靠接口契约解耦并行。
- **决策留痕**：每个拍板落进内容包（范式定案节）或协作文档，不靠口头记忆。
- **验证留证据**：合并评审产出 tsc 结果 + 浏览器实测描述（截图/行为），记录在接力卡。

## 三、同步机制（两人两 agent 怎么对齐）

| 通道 | 载体 | 频次 |
|---|---|---|
| 决策 | 飞书协作文档《knot 语义场内核·协作进度》（开 member 给杜） | 每次对谈/拍板后 |
| 范式 | 内容包（Knot_完整内容包.md，端云同步） | 更新即 overwrite |
| 产物 | knot 资产清单（knot-assets.json，画布即视图） | 每次落账 |
| 开发状态 | 接力卡（交接：当前完成/待办/坑）+ activity-log | 每轮收尾 |
| 代码 | GitHub 私有仓 zhilab/knot（待建 remote） | 每轮合并 |

## 四、纪律（红线，违反即停）

1. **不自动合并**：合并必须经中控验证（tsc + 实测），评审留证据
2. **同仓单会话 git**：同一仓库同时只有一个会话操作 git 元数据；合并用单次提交
3. **文件边界**：实现者不碰边界外文件；冲突先停，不硬合
4. **凭据零容忍**：真实凭据/密钥绝不进仓库（公开或私有都一样）
5. **决策必落账**：拍板不落资产 = 没拍板
6. **没有调查就没有发言权**：讨论/评审前先读现状（接力卡、架构文档、代码）
