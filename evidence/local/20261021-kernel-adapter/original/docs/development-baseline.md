# KONT / Knot 开发基准

决定日期：2026-10-21。状态：用户已确认方向；独立文档复核通过（仅本次文档），工程候选尚未接受。

## 核心决定

之明确：**后端对齐竞对，前端对齐 Apple。**

| 方向 | 开发时落实什么 | 判定方式 |
|---|---|---|
| 后端对齐竞对 | 查成熟的资产、上下文、协作、产物回流、运行可观测性与恢复机制；核对 Knot 既有实现后做复用、适配或补缺 | 具体行为、来源、版本、现有接口与测试；以完整任务验证取舍 |
| 前端对齐 Apple | 窗口与稳定对象身份、文件夹与项目组织、台前调度与现场切换、资源库与唤出、渐进披露、不同尺度的呈现和连续性 | 对照既有交互／设计文档，并由之判断真实工作是否易懂、顺手、可继续 |

成熟行为借鉴与源码复用分开。采用第三方代码前核对版本、许可、依赖和服务耦合；竞品报告中的建议不能自动成为任务或功能承诺。

Apple 对标落实到组织、操作和连续体验。工作站负责详细操作，内部桌面组织对象；窗口、卡片、图标及后续浮窗／组件引用同一现场。关系画布按需打开。暖橙与中性色等既有设计方向应先查；旧节点尺寸、材质与动效参数需按新承载验证，不能机械照搬。

## 贯穿两边的已有底线

1. **Agent 原生**：全部业务状态数据层可达，全部动作可程序化调用，变化可订阅；人和 Agent 走同一操作内核。
2. **AI 用得爽，人类看得懂**：人的界面先交代当前工作、真实活动、需要决定什么与下一步；完整结构、来源和证据留在执行层，避免把人变成信息处理工。
3. **自动织养，手动覆盖**：已授权范围内可自动整理、成结与维护；人工固定、排除、断开和隔离不能被悄悄撤销。
4. **保持资产颗粒**：稳定结／块 ID、内容、版本与 provenance 可继续生长；沿用既有命令和协议，不另造平行资产权威或通用命令总线。
5. **职责清楚**：Knot 拥有资产、供给、现场和业务动作；DSH 承担 Agent／Session／turn／工具执行，经薄适配接入。采用 DSH 插件承载，不把业务语义绑死在其私有接口。
6. **供给与授权分开**：查看、搜索、展开不自动加入供给；历史来源不递归授权；读、写、Agent 使用分别核对权限。
7. **呈现与运行分开**：收起／关闭不隐含停止、归档或删除；运行状态有真实事件依据，失败不能产生伪成功正式资产。

## 每张开发任务卡怎么写

沿用标准化工作流的每任务链，不新增管理系统。

1. **既查**：先查治理母本相关表、文件目录、项目既有产物／注册表／派工单。写“已有／无／以某来源为准”，附实际范围；未查项明确登记，不把检索不到写成从未设计。
2. **受理与拆卡**：写目标、来源、现有代码／测试、复用或缺口、最小改动、允许文件、授权边界、产物和验收方法。分别注明后端竞品依据与前端 Apple 依据。
3. **Maker 与自核验**：走共用内核，保留真实命令、退出码、覆盖与未覆盖项。验证优先服务层，再程序化检查；禁止用截图／模拟点击作为 Knot 的 Agent 验证路径。
4. **独立 Checker 与 Gate**：制作者不得自验收；检查上下文、事实源、权限、兼容、可靠性与设计基准。读回必须包含新内容；自测通过不等于产品接受。
5. **入档与收口**：登记 archive_id、检索键、摘要、证据指针和状态；按目标／监听回收／证据／验收／入档／记录／未决七格收口。

涉及共享母本、正式提交、远端发布或合并时，沿用其既有授权与工作流；本地文档落盘不等于跨窗口已采用或远端已同步。
