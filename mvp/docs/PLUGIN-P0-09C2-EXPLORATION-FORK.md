# 09C2 可追溯分岔核心

本候选为探索增加显式 1.9 来源屏障和同 owner 的 `fork` 操作；不接 HTTP/MCP、不改变默认初始化，不授权真实业务库迁移。分岔指定源探索 ID、历史修订与事件 ID，新探索 ID 和请求 key；事务内核当前 reader 与内容哈希，并原子追加新探索修订 1 和不可变来源。源与分支此后各自按 CAS 推进；分岔的分岔记录直接来源。

v2 历史的存储快照文本原样复制；v1 历史按确定规则升为 v2 空关系的语义副本。来源中的 SHA256 是源数据库快照文本的 UTF-8 摘要，不代表原文件或聊天来源。关系 ID 在各探索内使用。`load_v2` 在 1.9 返回固定来源锚或 null，仍按当前授权抑制关联说明；旧 load/save 拒绝分支。原 key 的成功分岔重放只返回不含正文的收据，不重新复制或覆盖。

迁移校验既有结构、历史与来源，拒绝漂移；旧 C1 版本屏障拒绝 1.9。运行中服务和其他 CLI 的安全性未由此证明；迁移真实库前须另行授权并核唯一写入者。技术复核不是产品接受。
