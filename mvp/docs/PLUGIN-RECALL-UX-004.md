# RECALL-UX-004｜完整留存、可信筛选与侧栏时间浏览

2026-11-17，基线cb63129。承接用户五项浏览器批注及事实不准、时间线不完整、进度条意味不明三项纠正。用户提供的截图可作为反馈证据；开发验证继续使用HTTP、SQLite、Node DOM，不自动截图或点击。

## 定义

1. 留存与展示独立。已登记项目及显式绑定的正常人类对话中，完整、有来源和原时间的用户消息均进入留存队列；不以“精选”或最近三段截断历史。仍排除系统、工具、子Agent、不完整及来源不明消息。已有授权身份与追加资产/manifest不变。每轮有限工作量采用轮转推进，可读来源不能因另一缺失日志或整项目新增量超过剩余额度而全部饿死。不能把元数据发现称正文已保存。容量或缺失明确报告，不把失败计为成功。

2. 事实分层：真实原话、整理回顾、历史文档方案、工作回顾分别标注，整理文字不是用户原话或新确认。来源未知理由留空。同名不同登记项目不合并，但项目卡显示已保存数量、日期覆盖与身份区别线索，进入项目直接读完整记录；无精选不显示空的双栏与空详情占位。

3. 可信筛选只控制显示。默认能阅读全部受权原话；提供明确的“全部记录/选择线索/整理回顾”等读法，显示筛选范围和命中依据。选择线索仅为原文逐字摘录或结构化answer，标候选，不推断决定与因果。完整记录仍可一键恢复；日期范围和来源数量可见，无静默删源。

4. 左侧项目导航下方显示纵向原消息日期浏览。拖动进入“回顾截至某日记录”，显示明确日期与已留存条数；它按所选真实manifest内原消息时间筛选，不能称当时完整快照。回到“全部时间/最新”恢复全量。真实留存版本保留为另一个明确的高级入口，单版本不显示无意义进度条。归档日和文档日不补成发生日。

5. 全局项目入口持续可见，可随时看其他项目。已发现尚无正文的项目可进入解释具体状态；不制造空业务项目。全局捕获状态不占项目正文大块空间，详细计数默认折叠且区分已发现、正文可读、已留存、缺失/尚未完成。

## 用户追加：同一项目与可重组的数据

用户已明确确认当前已留存的KNOT与Knot是同一项目，授权将二者关联到现有Knot，汇集受权原话。保留旧项目身份、资产和版本，不按名称扩展第三个未确认身份。关联记录作为既有普通source文档保存，包含canonical/source项目ID及用户原话依据；运行ready仅引用该不可变资产，不另存一套业务关系。启动时验证关联记录并派生别名路由，概览显示canonical，旧ID历史仍可明确读取。持续捕获用同一映射，新原话写canonical。

Agent整理不能被固定关键词限定。ProjectImportRequest新增可选recap，内容为现有decision-import/0.1完整整理包；服务端逐字核来源与日期，沿同一项目原子追加sources/archive/manifest。Agent可读取完整原话、重组新的curated_recap，再保留旧版本继续修订；整理不产生user_confirm。旧请求缺省不补recap以保持幂等。recap与archive_ref不可同时设置，仍遵守原source/材料/响应额度。schema、服务、测试同步，不增加平行资产权威。

补充允许：decision_archive.py、project_policy.py、project_repo.py、contract/v1/schema.json及领域测试、workbench.py的别名过滤与运行配置；主Agent负责。跨项目汇集仅使用用户已明确关联的两项目及现有受权sources，不转移owner或删除旧身份。

## 验证

用户要求所有发现内容留存，新增显式运行选项保存真实登记元数据为project-registration.json普通文档，使本机原文缺失的项目仍有可读登记记录；登记与正文数量分开，零原话不称完整历史。不复制宿主路径/账号/凭据，不创造用户消息或决定。该选项保存后持续生效，重复启动不重复建版本。缺失日志不能凭登记补写。只把用户确认的两项目关联，第三个同名登记继续保持独立。

超过三段历史会继续推进；缺失日志不饿死可读来源；批次可保存部分真实完整来源且重复扫描零新增；项目身份隔离。纯原话项目有可读内容，筛选可恢复全部；纵向日期控制与卡/侧栏联动、明确截至日期与真实版本区别、单版本无假进度条、可返回全局/切项目。真实入口按各项目逐一读回，不再仅用含人工回顾的Knot项目证明所有项目体验。
