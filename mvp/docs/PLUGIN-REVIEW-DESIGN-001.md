## 3. 正式布局：阅读先行，动作聚焦

### 桌面 ≥960px

256px 稳定侧栏 + 弹性主区。主区左对齐，最大阅读宽 960px，页面边距 32px；正文 15px／1.7，标题 24px／1.3、600。暖橙只表示当前选择与主动作，用实体面和细分隔组织内容。

侧栏从上到下：

- 品牌 40px，“所有项目”44px。
- 七项目平铺，每行最小 36px，当前行浅橙底；名称最多两行，不附每项三行统计。名称与数量来自真实列表，同名按现有 project_id 区分。
- “材料与思考”收为一个次入口。
- 分隔后是弹性日期区：顶行“时间”+ 当前日期，中间滚轮占满剩余高度，底行“最新”。来源覆盖说明进入 details。

布局落点：.app-sidebar 使用 height:100dvh、min-height:0、position:sticky、top:0、display:flex、flex-direction:column；导航部分 flex:none；.project-date-browser 使用 flex:1 1 auto、min-height:192px、display:flex、flex-direction:column；内部日期视口 flex:1、min-height:0、overflow-y:auto、overscroll-behavior:contain。轨道实际占用剩余高度，不只拉长装饰线。矮视口不足“导航+192px”时，项目列表区内部滚动，不能把日期轨挤成小按钮。

主区从上到下：

1. 64px 顶栏：稳定项目名；“截至 YYYY-MM-DD”或“最新”。刷新为普通文字操作，不再放第二个强调按钮。
2. 概况：有已保存回顾时先读 current.summary，再读 next.summary；无回顾显示“还没有整理这份项目资料”，下一步“找齐资料后，Knot 会给你一份可复制的整理指令”。只在此放“整理这个项目／继续整理”。不能从名称、commit 数、助手自述生成完成结论。
3. 轻量内容入口：“项目动态”“整理”“原话与资料”，高 44px。进入整理后，概况强调按钮隐藏，由当步接管唯一主动作。
4. 默认动态是一列纵向回顾：日期标题 → 人话变化标题 → 2–4 行摘要 → “查看出处 · N 条”。原消息、路径、版本和 hash 在 details 后。JSON、ID 和扫描日志不能代替摘要。
5. 日期未知另列“日期待核”，不塞进日历天，不用保存日补齐发生日。

所有项目首页：标题“所有项目”，一句“选择项目，查看进展并继续整理”，渲染全部真实项目。卡内只放名称、有出处的最近概括、最近可核日期；无概括写“尚未整理”，无日期写“日期待核”。选择一个真实项目后，唯一主动作是“打开这个项目”；未选时项目名称本身是普通导航，不显示无目标的整理按钮。

最新态七项目均有正式入口。日期定位到早期时，未来项目仍可从稳定导航辨认，置于“此日之后”弱分组；打开沿现有“该日尚无记录”呈现，不静默改日期，也不混入截至此日的项目集合。

### 整理展开

宽屏为 168px 五步列表 + 当前一步内容，间隔 24px；只保留一个编辑容器，不摆五个大空表单。所有节点可见，回看不重跑动作。当前可推进阶段用 aria-current=step，正在查看的节点用 aria-pressed，两者分开。

标题直接写：“找齐这次要整理的资料”“复制这份整理指令”“粘贴 Agent 的整理结果”“检查项目回顾”“保存这份项目动态”。产品不出现“工作面、实现交接、示意占位、manifest 工作台”。

## 4. 五步真实内容与转换

| 节点 | 默认可见内容 | 唯一强调动作 | 成功／失败 |
|---|---|---|---|
| 找齐资料 | 项目名、已留存清单、可读数、真实缺口、本步指令 | 生成整理指令 | prompt 成功进入第二步并显示全文；超限留本步，不静默截断 |
| 复制整理指令 | 项目与资料版本、本步指令、**默认展开的完整只读 prompt**、“复制后交给你使用的 Agent” | 复制完整指令 | clipboard 成功才写“已复制”并进入第三步；失败保留全文；普通按钮“我已复制，去粘贴结果”支持手动复制 |
| 粘贴整理结果 | 本步指令、回看本轮完整指令、标“Agent 的整理结果”的 textarea | 检查这份结果 | 非空后调用 prepare；成功进入第四步，格式／核源失败保留原文并指出字段 |
| 检查 | 起点、现状、已完成、阻碍、下一步、按日里程碑；缺口与逐段出处；本步指令 | 检查好了，继续 | 用户确认已读预览与缺口才到第五步；修改返回第三步，保留指令与结果 |
| 保存 | 准确项目名、将追加的动态摘要、本步指令、“返回检查”普通入口 | 保存项目动态 | 沿现有 import 准备／确认／提交，成功收据后完成；随后主动作“查看项目动态”，次入口“开始下一轮” |

“读取本机开发记录”是第一步可选普通按钮。collect 只返回预览 document，显示预览不等于已加入 prompt；用户选择加入并通过现有 project-import 成功保存后，显式取得新 revision／manifest_hash，再生成指令。未加入时写“本轮使用已留存资料”；无 root 时写“没有可读取的本机目录，可继续整理已留存资料”。主按钮不偷偷扫描或保存。

### 每节点的实际指令：默认可见，可回看

节点标题下固定“本步指令”，直接渲染以下文本；不是空 textarea 或“此处将显示提示词”。这些是人与未来 Agent 共用的动作说明。完整模型任务只有现有 project-review-prompt 一个来源，不能伪称五次模型响应。

1. **找齐资料：**“检查这个项目已留存的资料和缺口。需要补充本机开发记录时，先读取并确认加入资料；然后生成基于这份资料的完整整理指令。”
2. **复制整理指令：**“复制下方完整指令，交给你使用的 Agent。指令已经包含这次可读的项目资料、出处和返回格式，请让 Agent 按它整理。”
3. **粘贴整理结果：**“把 Agent 按本轮指令返回的完整整理结果粘贴到这里，然后检查。需要找回原指令时，打开‘回看本轮完整指令’。”
4. **检查：**“先读项目起点、现状、变化与下一步，再展开出处核对。留意没有出处或日期待核的内容；需要修改时返回上一步，确认后再继续。”
5. **保存：**“确认下面的项目和回顾内容，然后保存为一份新的项目动态。保存成功后，可以回到项目动态查看。”

第二步的说明后必须直接渲染服务响应的完整 prompt，不前端重组、截短或改写。已核 mvp/devtools/project_review.py 的 prepare_prompt：开头是“请根据以下项目资料，整体整理项目起点、当前状态、里程碑与工作回顾。仅返回一个严格 JSON 对象，不加 Markdown 围栏或额外字段。”随后有项目绑定与覆盖、全部可读 source.text 及原时间／定位、严格返回模板。按钮复制整段返回值，不只复制说明或屏幕可见几行。

第一步尚未生成时，“本轮完整指令”真实状态为“资料确认后生成”，不放假内容。生成后第三、四、五步可打开同一份只读原文；回看第二步显示当时实际复制的版本，不重新生成冒充原件。资料变化时显式“按最新资料重新生成”，旧返回文本保留并标“来自上一份指令”。prompt 回看同样受权限失效清理，撤权后隐藏对应正文并要求重核。

### 状态与恢复

只扩展现有会话的临时 UI 字段：selectedStep、currentStep、promptBinding、promptText、returnedText、checkedPreview、phase。不得新建业务 Store、数据库、模型通道或自动任务。promptBinding 始终是实际 project_id／revision／manifest_hash，导航项目不会改变它。

顺序为：资料已就绪 → 正在生成 → 指令可复制 → 等你带回结果 → 正在检查 → 待你检查 → 可以保存 → 正在保存 → 已保存。请求状态只在真实请求期间显示；已复制不等于 Agent 运行。点击节点只导航，不触发生成、核对或保存。

- 空返回：禁用检查，旁边“先粘贴整理结果”。
- prepare 失败：保留返回全文，指出段落与原因，旧检查预览失效。
- 版本变化：“资料有更新”及普通按钮“按最新资料重新核对”；用户操作后才显式重绑并重核。
- save unknown：“正在确认这次保存的结果”，唯一主动作“恢复这次保存”，只重试确切原请求，不新增 key 或重新生成内容。
- 有输入、待保存或 unknown 时沿现有编辑锁保护项目和日期，说明“先完成或结束这次整理”；出处阅读、节点回看仍可用；收起不清空输入。
- 无可恢复会话时只能“开始新一轮”，不从旧回顾推断本轮完成。后期 Agent 沿相同节点与真实回执接手，不摆假自动运行开关。

## 5. 连续日历滚轮与每日分组

### 日期域和标记分开

当前 projectDateDays() 返回的受权真实日期，只作记录标记集合，不能继续作 range 下标。交互域是最早可读日期到当前 Asia/Shanghai 日历日；选日仍表示现有 projectCutoff 的“截至当天”。单记录距今天多日仍能逐天空滚；仅起止同日才不滚；无可定位日期写“暂无可定位日期”，不造起点。

先用现有 projectMessageDay 把来源毫秒转成上海日期，再将日期年月日映射为 UTC 整日序号做差；不能对原时间直接累加24小时冒充换日。相邻日永远 index+1，跨月／年／闰日不断档。日历空天不意味着有资产。

### 轨道与操作

日期视口占满侧栏剩余高度，每天 36px 等距，中间固定选中带和 2px 橙色短线；显示日期、星期，月首加月份。真实记录日加实心点；空天只有淡刻度，不加假计数、假事件。chronology 的 observation_times 至多128项，**无点只表示当前投影未给标记，不能证明当天没有记录**。

渲染“可见行+上下各4行”的有界窗口与上下 spacer，日序号范围完整，不一次生成数年 DOM。顶部／底部 padding=(视口高−36px)/2，使起止日也能到中央。

- 滚轮／触控板：只在日期视口内滚动，停约100ms吸附最近一天，吸附最多120ms、无弹跳，不全局拦 wheel。
- 拖动：约36px一天，超过8px才 capture；向上拖列表看到更晚日期。pointerup／cancel／失焦都释放捕获并清理；拖过抑制一次误点击，cancel 不误提交。
- 点击日期直接居中提交。键盘 ↑早一天、↓晚一天、PageUp／Down七天、Home最早、End今天；“最新”独立解除截止，不能等同 End。
- 保留 #project-date-range 作为同一日值的可访问控件／事件适配，min=0、max=日差、step=1；aria-valuetext 报完整日期和记录标记，装饰日期行不重复进入 Tab 顺序。
- 拖动每帧最多更新一次预览；已可读分组即时联动。需读取时最多每120ms合并到最后一次选择，松手提交最终值；按 generation 丢弃过期响应。请求期间隔离旧正文，不把它冒充新日期。
- 进／退项目和回首页保持同一日期；预览不业务保存。有编辑锁时按 §4 保护。

### 主区双向联动

主区日期标题可 sticky，日内按真实来源时间升序；无精确时间保持稳定原顺序。用可核发生日或原消息日期；只有留存日的条目明确归“某日留存”，不能叫发生日。milestone.on=null 进“日期待核”。未保存返回不能当已保存动态。

在所有项目中选择 D，更新截至 D 的项目集合和当天新增项目提示。在项目中选择 D，保留当前可读日期组并定位当天。空天显示“当天暂无可读记录”，附近日期组保留其实际日期。

用户手动滚主区，以内容视口上部 30% 的阅读锚线确定当前日组。滚动过程中侧栏跟随，停约 100ms 后提交定位日期。定位时保留当前组及其视口偏移，也保留后续日期组以供继续滚动。

编辑期间保留原日期与输入。主区滚动及日期控件都进入同一选择函数，由 source 标记发起者。

日期驱动程序定位标 source=rail，定位期间主区 scroll 不反推；真正 wheel／touch／key 用户意图立即取消程序定位，改以用户滚动为准。请求 generation 同时绑定项目、版本、日期，只有当前响应可显示。撤权沿既有 invalidate／recheck 清除旧正文、详情、日期点和 prompt 回看，不从旧 scene 补回。这是同一权威的阅读投影，不是历史完整快照。

## 7. 昼夜、窄屏、减弱动效

浅色：画布 #F6F5F2、侧栏 #EEECE6、内容 #FFFFFF、正文 #302E2A、辅助 #6E6860、分隔 #DEDBD4。深色：画布 #191817、侧栏 #201E1A、内容 #242321、正文 #EDEAE4、辅助 #B6B0A6、分隔 #4B463E。橙底 #FF9500 配深字 #2D1C08；焦点环2px，不只靠颜色标状态。昼夜共用结构，主题直接换语义色，不整页变色动画。

| 场景 | 普通桌面 | 深色或<960px | reduced-motion |
|---|---|---|---|
| 日期／步骤选择 | 状态立即，背景100ms | 背景60–80ms | 立即 |
