# CONTEXT-LIST-002｜项目列表呈现（前端）

2026-11-17，基线 `8a57c11`。后端在 CONTEXT-LIST-001 给主列表加上取舍与排序后，前端必须让人**一眼知道哪个项目现在值得打开**，而不是平铺一排同样的卡。当前 `workbench.html` 只渲染标题、"已留存 N 条材料/原话"和 `saved_at`。

## 前置

依赖 CONTEXT-LIST-001 的契约：`items[]` 含 `last_activity_at`、`state`；顶层含 `hidden_count`。本卡不得自行改后端或改契约；若后端未合入则本卡挂起等待。

## 定义

### 主列表卡片

每张卡显示，顺序固定：

1. 标题（`title`）
2. 最近活动：`last_activity_at` 转为相对时间（今天 / 昨天 / N 天前 / N 个月前）；`null` 显示「无时间记录」，不得显示「今天」
3. 留存：材料数 + 决定数，沿用既有句式，`decision_count == 0` 时不显示决定段
4. 状态标记：`active` 不额外标注；`dormant` 加一行「超过 7 天没有新内容」

卡片不显示项目 UUID、manifest hash 或任何内部标识。

### 折叠区

`hidden_count > 0` 时，主列表下方固定一行：「另有 N 个项目没有留存内容」，可点击展开为紧凑列表（仅标题 + 一条说明）。展开状态不改路由、不移卡位、不发出新请求。

`hidden_count == 0` 时不渲染该行，不留空占位。

### 空状态

- 请求成功且主列表与折叠区都为空：「还没有可看的项目」+ 一句下一步指引（用「补充材料」入口）。
- 请求失败：沿用既有错误呈现，不得显示成「还没有项目」。

### 排序与来源

前端按后端返回顺序直接渲染，不重排、不再排序。相对时间以请求发起时刻为基准计算一次，同一次渲染内保持一致。

## 验收

1. Node DOM 测试：给定 3 个 `active`、1 个 `dormant`、`hidden_count=5` 的响应，断言卡片顺序、相对时间文案、dormant 标记、折叠行文案与展开行为。
2. `last_activity_at=null` 渲染为「无时间记录」，不出现「今天」。
3. `hidden_count=0` 时折叠行不存在于 DOM。
4. 请求成功但两处都为空时显示空状态文案；请求失败时不显示空状态。
5. 展开折叠区不触发新的 `/api/projects` 请求（计数断言）。
6. 既有项目面板测试保持通过，无新增失败。
