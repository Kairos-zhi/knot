# Knot 一周开发派发卡

## 本周目标与开工基线

让接手同事能在隔离环境启动现有历史走查，清楚看到资料范围，能读、选、保存、回来和处理失败。历史样本只覆盖近期三份开发文档。用户已提出“我不知道怎么用”，并追问更早决策、决策方式和路线为何变化。验收需明确区分文档中可定位的记录、人的解释和本批资料未覆盖的内容。空结果不能证明历史未发生，聊天总结和库外记忆不能当作 Knot 的检索结果。

- 工程基线为候选分支 `codex/p0-05c3-source-mcp`，HEAD `f907b74596902559c1ebab89389aecedd2ccd679`，tree `3fdb276cb1cf8bf71cf35a80cb85b409b7caf5e2`。候选已推送，未入 main。从 [Knot 仓库](https://github.com/Kairos-zhi/knot.git) 拉取指定候选分支，核对 HEAD 和 tree 后从该提交开工。若分支头已变，暂停并请中控核定。领卡时登记未提交产物和实例归属。此前三分支推送仅是历史。
- 私有交接附件 `HISTORY-01.md` 与 `GATE.json` 证明三份近期真实文档已按固定白名单、原字节和专用 reader 进入独立 1.9 库。技术 Gate 有限通过，Gate 签发时尚未开始人的体验。沿用该成果，不重做导入。保留来源的 `provenance_verified=false` 和 `import_evidence_checked=false`。来源未知时，人的本地清单回源与产品来源投影分别标注。
- 阅读 `AGENTS.md`、`STATE.md`、`QUEUE.md`、`mvp/docs/development-baseline.md` 与阶段路线 `mvp/docs/PLUGIN-CODEX-PHASE1.md`。以候选 `mvp/docs/HTTP.md`、`mvp/contract/v1/endpoints.json` 和源码确认接口。当前 MCP 有 11 个工具。资料正文和停点是本机结果；贴入当前聊天或由聊天模型读取时进入模型可见历史，撤选不会擦除已返回内容。
- 执行中控为聊天 `01a1ac34-0402-7740-b089-84fa2557beff`。本包供人类同事领取，由中控登记唯一负责人、冻结允许文件、排依赖和签有限 Gate。本窗口仅准备卡，不另行派发。人类同事主开发，GPT-6.1 可协助自核，独立 Reviewer 按反例复核。人的体验及接受由实际使用者给出。
- 本周不新增桌面 UI、语义搜索、通用导入、reader 生命周期或原始聊天适配。工作范围是准备可供派发的卡，后续实施、私有资料交接和使用测试依各卡授权执行。无本轮 push、merge、deploy、额外真实模型或生产安装授权。私有代码、固定资料、运行日志和绝对路径通过单独授权交接，不复制进 Git。

## 排期假设

五个工作日，开发 A、B 各一人，另有兼职独立 Reviewer。开发合计约 48–68 人时，Reviewer 约 14–16 人时。下表是人时估算。若只有一名开发，先做 01、02、04 的最小链与必要回归，03 缩为固定反馈说明，余项另排。先给 Reviewer 排出定义和验收时段，卡未通过定义复核前只做静态既查。依赖晚到时保留定义、证据和停点，将后继卡标等待。

| 工作日 | 开发 A | 开发 B | Reviewer |
|---|---|---|---|
| D1 | 01 既查和定义 | 02 既查和定义 | 01、02 定义复核 |
| D2 | 01 实现、自核及 03 定义 | 02 实现、自核及 04 定义 | 03、04 定义复核 |
| D3 | 03 按已冻结接口实现 | 04 按已冻结接口实现 | 01、02 独立检查 |
| D4 | 03 定向收尾，准备 05 | 04 定向收尾，准备 05 | 03、04 独立检查及 05 定义复核 |
| D5 | 05 集成证据 | 05 交接与缺陷记录 | 05 独立检查，中控汇总 |

文件与共享接口归属由中控冻结。01 负责启动器与引导，02 负责目录，03 负责反馈呈现，04 负责操作与恢复，05 负责整合。共享文件指定唯一编辑人，A、B 按已冻结接口并行。

所有代码卡共同门槛。开工前交最小定义，列精确输入、契约、错误及允许文件，独立复核通过后实施。完成须提交自核命令、结果与失败记录、源版本和证据位置，由独立 Reviewer 给有限结论。下面的文件仅是候选落点，以冻结定义为准。保留 11 个工具的名称、描述、顺序和输入 schema 兼容。先用合成资料验证，再在授权范围内引用 HISTORY 附件。既有成功证据可复用，回归针对变更。

## CP1-WEEK-01 · 隔离启动与交接

**P0｜开发 A 10–14h，Reviewer 3h｜依赖** 冻结候选、HISTORY Gate 与私有 R4/历史启动入口，只读参考。

- **范围与候选落点** 审查现有入口，将经批准可移交的最小启动、检查、停止与环境说明提炼到一个开发工具位置和一份说明，候选为 `mvp/devtools/` 与 `mvp/docs/`。通过受控的本地配置引用经授权的材料，不把历史私有脚本整包复制。配置、结果、日志、数据库与凭据按归属隔离。保持现有 HTTP、MCP 和单写者；本卡不开发新导入器或自动安装。
- **开始与交付** 中控确认可交接范围、平台和现有 Python/MCP 环境。交干净机器配置清单、启动/状态/停止入口、最短操作例与隔离证据，命令由操作者执行。
- **验收与完成** 同事使用新私有根和合成库按说明启动，完成一次真实 MCP 查询，随后停止并核自己进程已退出。缺依赖、错候选、占用、无效路径或参数均固定失败，且不访问生产库或开启第二个写者。正文/凭据不出常规回执。附正反例及独立通过记录。

## CP1-WEEK-02 · 可见资料范围和长文发现

**P0｜开发 B 8–12h，Reviewer 2–3h｜依赖** HISTORY 固定资产清单、`mvp/codex_mcp.py` 及 `mvp/docs/HTTP.md` 的短文本搜索与长文切片契约。可与 01 并行定义。

- **范围与候选落点** 让操作者能展示本次走查的有界目录、时间或主题覆盖、可用阅读方式。首选由已授权固定清单生成本地提示，作为 01 的配套说明/本地投影；候选 `mvp/devtools/` 的目录输出和测试、`mvp/docs/` 的范围说明。长文凭资产 ID 和内容哈希显式切片。目录只描述授权附件与可见范围，不替代 reader，不新增端点、不更改关键词搜索。
- **开始与交付** 核准清单可公开给本轮参与者的字段，并确定权限变化后目录是否仅提示覆盖而不展示条目。交目录/提示、长文操作例、空结果和较早历史问题的答复范例。
- **验收与完成** 既有短文搜索结果保持，长文能从目录进入授权切片。超出三份资料范围和搜索无结果时能分别给出范围提示与下一步，不从聊天历史补造决策或动机。错哈希、撤权或非清单资产不能读到正文；未经授权的私有标题不进入目录。Reviewer 实测长文、无命中和撤权三个场景。

## CP1-WEEK-03 · 人可读停点、分支和操作反馈

**P1｜开发 A 10–14h，Reviewer 3h｜依赖** 01 的回执格式；现有 `mvp/plugin_projection.py` 与 `mvp/codex_mcp.py` 的 v2 保存、加载、分岔结果。

- **范围与候选落点** 在同一薄操作入口展示动作、探索与版本、是否历史分支、下一步和本地结果位置。将冲突、权限变化、未提交、未知结果按既有契约表达；没有可信结论时保留未知。停点仍使用现有文本，关系及来源按现有投影，不做新 typed 思考对象或另建状态权威。候选 `mvp/devtools/` 的投影与单测、`mvp/docs/` 的反馈对照表。
- **开始与交付** 先冻结回执字段、可见面和固定错误文案，对齐 01 与 04。交示例、映射测试和本地结果查看说明。
- **验收与完成** 操作者只看回执即可区分当前、历史、分岔和失败，能找到本地停点。撤权后关联提示遵守产品抑制，畸形结果不显示成功路径；常规日志、错误输出不带正文、笔记、理由或 token。独立 Reviewer 用历史分岔、撤权、畸形回包检查。

## CP1-WEEK-04 · 显式保存、返回与同键恢复

**P0｜开发 B 12–16h，Reviewer 3–4h｜依赖** 01 的隔离入口、03 的反馈契约先冻结；以 HISTORY/R4 和组合验证证据为起点。复用 `knot_save_exploration_v2`、`knot_load_exploration_v2` 与 `knot_fork_exploration`。

- **范围与候选落点** 将现有逐次调用的保存、按版本返回、显式恢复做成同事可执行的步骤。沿用发送前的原请求与独立绑定、明确预期版本、操作后回执；超时、丢响应或收据落盘失败时可保留未知状态。重启可查看状态，恢复只在操作者选择后使用原请求和同 key。候选 `mvp/devtools/` 的已审查状态/入口及测试、`mvp/docs/` 的恢复说明。无自动保存、重试、换 key、平行写 API 或 exactly-once 承诺。
- **开始与交付** 定义明确写入边界、原请求和结果文件的本机位置与内容分类，复用 01 的入口。交跨进程脚本、操作说明和故障注入证据。
- **验收与完成** 保存自选材料与停点，退出后按版本加载，能指出已保存内容。真实后端提交后故意断响应，核桥只有一次连接/请求，原 key 和请求摘要已耐久保存；再次启动不会发送，显式恢复同 key/正文得到原收据，SQLite 只有一个对应修订及事件。坏绑定零上游；同键异内容、旧版本冲突、reader 撤权均可辨认。Reviewer 复跑关键故障链。

## CP1-WEEK-05 · 整合回归与交付检查

**P0｜A 主责，B 协作合计 8–12h，Reviewer 3h｜依赖** 01–04 的独立有限通过和同一组合候选。可提前设计验收矩阵。

- **范围与候选落点** 串接启动、范围说明、短查找/长读/回源、变更选择与关系、历史分岔、停点保存与返回和未知恢复；候选为 `mvp/tests/` 的窄回归、`mvp/docs/` 的操作说明与私有证据索引。无需重跑已接受的完整历史矩阵，无新功能开发。
- **开始与交付** 中控固定实际组合版本、私有资料范围与可接受门槛。交程序化回归、清洁退出证明、同事操作清单、缺陷/待用户验证台账；技术、人的体验和发布分别列状态。
- **验收与完成** 在干净私有库走通一条跨进程链，确保旧 11 工具描述符兼容，正反记录可关联到调用、HTTP 与数据库。必测未授权长读、过期版本、未知写恢复、提前停止和服务收尾。另给同事一个非预设问题，让操作者自己选资料、改变方向并找到停点。若尚无授权让人运行，标记“人的体验待验”，只交技术候选。任何越权读取、正文出安全回执、自动重发或旧工具不兼容均阻断交付。中控签有限 Gate 后保留剩余缺口。
