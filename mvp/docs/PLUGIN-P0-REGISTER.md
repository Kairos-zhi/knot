## P0-03 多 actor 幂等归属

**遗漏依据**：`http_server.py` 的同步claim重放只比较body，journal key未保存actor；`bundle_jobs.py` 已比较actor+body。旧“幂等绑actor”概括漏了claim。

**触发/责任**：多actor写入口启用前；后续Codex Maker，未参与实现的Checker，之Gate。工程允许范围拟为http_server及针对性测试、契约说明；不借机扩写授权模型。正式实现前固定当时HEAD。

**关闭条件**：同actor同key同body可重放；跨actor同key不能返回另一actor结果；不同body拒绝；旧无actor journal条目有明确失败封闭策略；重启后同样成立，拒绝/重放不新增事件或seq。需隔离合成库反例，不碰在用journal。

**证据边界**：这是静态发现的身份归属缺口；HTTP已先鉴权，重放值是CommandResult，不含正文。不把它夸大为已证正文泄漏或已有逐claim写ACL被绕过。初版仅静态发现。增量候选 `2ef3410` 已修复并经独立 Checker 绑定，随 [#52](https://github.com/Kairos-zhi/knot/pull/52) 发布草稿。主线缺口及接入 Gate 仍开放。

## P0-04 正文输入与 reader 边界

**遗漏依据**：交接包提出选择/预览，但未有宿主实际输入证据；1.6迁移仅给历史资产local-user reader，先导入后配置另一actor可能不可读；重复导入按hash跳过不补授权。旧凭据不内联建议未进入明确前置卡。

**触发/责任**：接入真实材料正文或多身份前；后续宿主适配Maker与授权Checker。允许范围先为能力核查、隔离样本和测试；授权服务/宿主适配实现须另固定文件清单，不靠提示词代替服务控制。

**关闭条件**：区分meta与content；token→actor由服务解释，不由工具参数自报；覆盖先导入后配置、换token同actor/异actor、重复导入不扩权、显式reader授权/撤权和缺表拒绝。模型可见工具正文返回即已输入；撤选仅影响未来受控构建，不承诺擦除宿主历史。凭据类材料默认排除，扫描/显式排除规则用合成样本验证，不能宣称扫描绝对无漏。未经批准不把真实密钥送入工具或模型。

**增量状态**：P0-04A 已核本机机制但未找到可验证的 Knot 宿主，真实 canary 未运行。P0-04B `85417d5` 是本地未发布的纯内存投影，28 项定向测试及独立复核通过，只保留 ID 与有限 kind；元数据/ID 仍可含敏感性或关联性。P0-04C 本地 `df0b9a1` 接官方 SDK 只读 MCP hash 查找，默认 CI 依赖收集问题已修；独立定向36项通过、全树只收集531项并绑定最终提交，尚未推送或注册宿主。这三项都不关闭正文输入、持久选择、reader 生命周期或真实宿主验证。

**P0-04D 后续证据**：本地封装 `8f59798` 复用 C，不改核心。用临时配置中的真实 Codex CLI app-server 完成插件发现/安装、MCP启动及一次带有效认证的合成GET；删除临时包 env_vars 后启动失败、HTTP请求0。独立40项定向通过，依赖清单补充后再独立通过4项包测试；535仅为收集数。只证明隔离的同机开发包接入，不能倒填A已验证真实正文，也不证明当前桌面安装、模型输入或产品接受。后续进入选材/正文与reader边界，不继续把封装当缺口。

**P0-04E 后续证据**：本地 `53312e4` 增加 `knot_read_asset`，按指定ID读取至多8192 UTF-8字节的plain/markdown文本；同token读取meta与content，服务显式 `require_reader=true`，拒绝single-user或无reader，核正文hash后仅返回资产锚点/MIME/正文。独立最终152项回归、24项反例通过；真实Codex+临时SQLite六例/8 GET通过。Checker发现的DEL控制字符漏判和撤选表述已修复，原失败保留。明确凭据标记与当前token排除是有限规则，不是通用敏感分类。未新增grant/revoke或持久选材接口，不把每次指定等同人已确认；已返回正文不能靠撤选擦除。未推送/在用安装/模型调用，P0-04继续开放。

## P0-05 来源与实际查找

**遗漏依据**：`import_baseline.py` 固定origin=v0.4，事件时间取文件mtime；现行`/assets`按hash查找，不是全文关键词查询。导入/FTS已有不能当对话检索已交付。

**触发/责任**：导入Codex/Hermes聊天或承诺“找到以前讨论”前；后续来源适配Maker、独立Checker。先选明确样本、只读结构及冻结映射，禁止默认全库导入；实现前再定允许模块和接口版本。

**关闭条件**：消息ID/角色/顺序/分支/工具/附件/定位及缺失项明确；文件时间不冒充消息时间；重复/追加/失败重试与来源保留验证；关键词查找入口及正文授权有契约，不能把已有FTS表充当用户可调用搜索。材料中的提示词保持数据身份。不会每换一个问题就临时另造一套专用流程。

**P0-05A进度**：本地 `524399f` 接共享只读搜索及MCP工具，最多8词/128 UTF-8字节，Unicode casefold字面子串AND，支持连续中文，不做语义推断或NFC。只查reader可读且通过E短文本策略的plain/markdown；结果仅ID/hash/MIME/has_more。最多扫描1000授权候选，1秒合作式预算及100ms锁等待，未能确定完整首批时固定错误、无partial。独立238+26项通过，真实Codex+临时SQLite12例/13 GET通过；545只是收集数。未发布代码，长文、全库索引及聊天来源仍未关闭。

## 不升级为本轮 P0 的项

对象级SSE、通用cancel/调度、云端存算分离、完整客户端、全库同步不因旧建议立即进入本轮；需要实际使用缺口和单卡依据。旧备份/导出清理不顺带执行。P0工程卡完成前也不得假称插件或产品可用。
