# UX-001 · 从开发控制台回到人的思考入口

2026-11-14。用户明确反馈“实际上不太好，最起码我看不懂”。本卡纠正38735e3把开发接口直接呈现给人的问题，不把先前技术通过等同体验通过。

允许：workbench.html、test_workbench_usability.py、本卡；原页面逻辑测试可调整DOM适配器、与新界面文案一致的定位及prepared草稿归属fixture，保持权限、精确请求次数、真实预览与未知状态断言。业务API、保存/未知恢复、私有导出策略和11工具不变。原运行中演示使用同一HTML/脚本文件，刷新后可查看；不自动刷新人的页面或读取真实资料。

默认首页只有三项：“继续上次思考”“找一份材料”“留下这次想法”。首页解释用途、第一步和未自动保存。编号/hash/字节偏移/原始状态/项目导出收进明确标记的高级区域。默认不加载业务数据、不自动阅读/保存/翻页/恢复。

继续：明确请求已保存清单后，用真实保存时间及列表顺序标识；不伪造项目名或笔记摘要。点一条记录直接显式读取对应停点，显示实际文字和材料按钮，不要求复制ID再点加载。材料按钮一次显式读取一页，正文只以文本展示；读取后可在本页用首行作临时显示名称，以asset_id+hash绑定，不把首行当验证过的来源标题。不可用材料抑制名称与阅读，原权限检查仍在。

记录：明确开始新想法或从已打开版本继续。草稿仅在页面，保存前展示将保存的文字、选材/关系数，再由独立按钮确认。known saved/unknown/prepared分别用人的话反馈及可执行下一步；digest和内部编号仍保留在高级校验详情。unknown不可另起保存或取消，仍需明确查看/恢复原请求。

保持进阶项目包完整预览和明确确认；整个分支默认折叠，不能改成后台上传。材料可读不代表已选入或保存，页面用“阅读”“加入草稿”区分。

验收以程序化DOM/HTTP/现有测试为准：初始无业务请求；首页无必填技术ID；清单打开一次GET、材料一次单页GET；草稿/确认/未知锁定不退化；恶意正文只作文字；高级导出兼容。禁止截图/模拟点击验收；人的理解和体验由用户实际判断。

## 用户追加：对齐既有设计基准并引入界面设计

已完整回读docs/design/principles.md、system.md、product/interaction.md、philosophy.md，以及历史design-v1/form-layer-v1与Apple设计系统/连续性研究。当前原则优先于旧画布尺寸、红绿灯与“错误沉默”历史取值；不恢复已移出的桌面承载。

采用：工作在前/工具在后；熟悉的对象与动作；当前焦点明确；一个主要强调语义；渐进披露；阅读不等于选入或授权；页面切换保留原现场；无真实Run不显示Agent执行或百分比。视觉沿用Knot暖橙#ff9500、中性灰、16/24/32间距候选、少量圆角及分组，不以毛玻璃/动画代替状态。浅色暖橙按钮采用深色文字保障对比度，深色模式另配色，不照抄旧小卡片字号。

界面结构：左侧稳定个人空间导航，右侧单个当前工作区；工作区顶部显示当前在查看/阅读/写作及真实状态；中间优先正文和思考，不堆治理表单。窄屏转为上方紧凑导航，内容顺序不变。首页三入口是工作导航，不是三张营销卡片。未实现项目文件夹不作假目录；项目包保留在进阶分支。

原生控件/键盘焦点、足够点击范围、中文长文、深浅模式、减少动态效果与渐进详情作为设计验收项。参考[Apple布局](https://developer.apple.com/design/human-interface-guidelines/layout)、[侧栏](https://developer.apple.com/design/human-interface-guidelines/sidebars)、[渐进披露控件](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls)，具体Web尺寸仍为本地设计候选，不声称Apple规定Windows像素值。

## 实现与 Maker 核验

已实现稳定侧栏、单一当前工作区、动态标题与真实状态、中性灰与暖橙、正文宽度约束、窄屏与深色样式。编号和校验信息保留在默认折叠详情；已有正文以 textContent 展示，不转为 HTML。打开记录、打开一页材料、加入草稿和保存保持独立显式动作。
